# Output

A `change-auditor` run writes no working file. It passes every payload between commands over stdin and stdout, and its result carries the run token, the rendered projection's run-level fields, every finding verbatim, and the one command that reproduces the complete projection from the sealed run. A bundled Python runner is `audit-change`'s only command boundary and performs every file and store operation the audit needs, reading back the retained input included.

Two change audits dispatched at once from one worktree, each against its own candidate, therefore return verdicts that each read only their own candidate and their own run.

# Value

Truth brought to a lower layer. `spx/13-plugin-and-runtime-conventions.adr.md` requires every scratch directory to come from a unique-per-invocation source and prefers pipes over intermediate files. `audit-change` and the `change-auditor` wrapper give no direction on working files. Auditor sessions invent their own names, and the names collide. A collision cross-reads one candidate's material into another candidate's audit, so every Maintainer must run change audits one at a time.

# Frame

## Received evidence

- On 2026-09-27 two `change-auditor` sessions ran at once from one worktree, each against a different local draft. Both wrote files named `render.json`, `input.json` and `findings.json` into the dispatching session's scratch directory, which every subagent that session launches shares. One session read the other's file, and its run stayed unsealed. The SPX run journal itself held the correct candidate for each run.
- Later change audits on 2026-09-27 again saved their rendered projection to a fixed `render.json` in that shared scratch directory, and one saved it to a fixed `ac_render.json` in the system temporary directory.
- The rendered projection of one change audit measured about 55 KB on 2026-09-27. Each auditor that saved it to a file did so because the whole projection did not fit its result. Each also stated that `spx verification run render` reproduces the projection byte for byte from the sealed run.
- `src/plugins/spec-tree/agents/change-auditor.md` directs the wrapper to return the run token and the rendered projection unchanged, and forbids editing files. It names no location for a working file.
- `src/plugins/spec-tree/skills/audit-change/SKILL.md` passes every scope and finding payload over stdin and names no working file.
- On 2026-09-28 a `change-auditor` session auditing this Change's draft improvised a line that redirected `spx verification run input` into a file under `$TMPDIR` and removed it with `rm -f`, and it stopped at the operator's ask rule for `rm`. `audit-change` prescribes no `rm`.
- `review-changes` runs every operation through its bundled Python runner and forbids invoking `spx journal`, `git`, `mktemp`, `rm`, `date`, `printf` and its scripts directly, because the runner is its only command boundary.
