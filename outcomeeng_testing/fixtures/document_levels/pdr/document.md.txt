# Session retention

DEFINES retention window AS the span after which an ended session leaves the listing.

GOVERNS the retention of ended sessions
SO THAT operators reviewing sessions
CAN RELY ON an ended session staying listed for its retention window.

## Verification

### Test.Mapping: window-by-state

Each session state maps to the window its listing follows.

| Case   | Window         |
| ------ | -------------- |
| active | not applicable |
| ended  | seven days     |
| failed | thirty days    |

### Test.Scenario: expiry

- sweep-removal:
  - Given an ended session whose window elapsed
  - When the sweep runs
  - Then the session leaves the listing
  - And the listing count drops by one

### Test.Compliance: expiry

- no-early-removal: NEVER a session leaves the listing before its window
  elapses.
- expiry-removal: ALWAYS a session whose window elapsed leaves the listing at the next sweep.

### Evaluate: window-readout

A listing summarizer states each window in days over curated sessions.

| Case  | Input            | Expected output             |
| ----- | ---------------- | --------------------------- |
| ended | an ended session | the window reads seven days |

### Audit

- window-observable: ALWAYS the listing states each window in days an operator can read.
