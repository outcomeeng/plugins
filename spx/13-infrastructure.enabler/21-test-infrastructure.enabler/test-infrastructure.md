# Test Infrastructure

PROVIDES a unified quality gate covering static analysis, type checking, linting, and test execution for all implementation code, plus the placement guarantee that the marketplace's own test-infrastructure implementation lives at its declared home
SO THAT the marketplace's Python scripts, validation tools, and test harnesses
CAN be verified for correctness before changes reach the main branch, with the test-infrastructure home kept outside `spx/` and outside any `tests/` directory

## Assertions

### Scenarios

- Given a pinned `outcomeeng/spx` checkout without the corpus directory, when a test asks the harness for the corpus, then the run fails naming the missing path and neither passes nor skips, per [`spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md`](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([test](tests/test_spx_fixture_corpus.scenario.l1.py))

### Mappings

- ALWAYS: `just test-l3` runs every test whose file name carries the execution level `l3` and no other test, and `just test` naming an L3 test runs it, per [`spx/13-infrastructure.enabler/21-test-infrastructure.enabler/14-l3-tests.pdr.md`](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/14-l3-tests.pdr.md) ([test](tests/test_l3_tests.mapping.l1.py))

### Compliance

- NEVER: a test harness under `outcomeeng_testing/harnesses/` leaves bytecode beside a shipped script, so that every argv a harness module writes as a list or tuple beginning with `sys.executable` and running a script file carries the interpreter's no-bytecode option, importing a harness turns bytecode writing off for the process, and an in-process load of a shipped script leaves no `__pycache__` directory and no `.pyc` file beside it, per [`spx/31-outcomeeng.enabler/31-verification.enabler/31-test-verification.enabler/15-test-infrastructure.pdr.md`](spx/31-outcomeeng.enabler/31-verification.enabler/31-test-verification.enabler/15-test-infrastructure.pdr.md) ([test](tests/test_harness_bytecode.compliance.l1.py))
- ALWAYS: every subprocess a test harness under `outcomeeng_testing/harnesses/` starts to run a shipped script carries the interpreter's no-bytecode option however the harness builds its argv, and after a full `just check` no `__pycache__` directory and no `.pyc` file stands under `dist/`, per [`spx/31-outcomeeng.enabler/31-verification.enabler/31-test-verification.enabler/15-test-infrastructure.pdr.md`](spx/31-outcomeeng.enabler/31-verification.enabler/31-test-verification.enabler/15-test-infrastructure.pdr.md) ([audit])
- NEVER: a tracked file of this repository lies under a `testing/fixtures/orchestration/` path — the shared orchestration fixture corpus is read from the pinned `outcomeeng/spx` checkout and never copied into this repository, per [`spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md`](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([test](tests/test_spx_fixture_corpus.compliance.l1.py))
- ALWAYS: the tests that read the shared orchestration fixture corpus obtain its directory from the harness under `outcomeeng_testing/harnesses/` that resolves `testing/fixtures/orchestration/` inside the pinned `outcomeeng/spx` checkout, per [`spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md`](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([audit])
- ALWAYS: GitHub Actions runs the full quality gate on `pull_request` and on push to `main` by invoking the `just check-full` gate recipe with the gate's toolchain provisioned at the project's declared Python version, never an inlined or filtered subset beyond the skip of the L3 tests [`spx/13-infrastructure.enabler/21-test-infrastructure.enabler/14-l3-tests.pdr.md`](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/14-l3-tests.pdr.md) declares and never a soft-passed step, per [spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([test](tests/test_ci_gate.compliance.l1.py))
- NEVER: a file in the repository carries the words "on" and "demand" joined by a hyphen, by an underscore, or directly, in any letter case, per [`spx/13-infrastructure.enabler/21-test-infrastructure.enabler/14-l3-tests.pdr.md`](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/14-l3-tests.pdr.md) ([test](tests/test_l3_tests.compliance.l1.py))
- ALWAYS: in every changeset that changes the CI workflow file, the codex-cli version the workflow pins equals the codex-cli version the maintainers' development host runs, and the pin carries no registry-update annotation, per [spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([audit])
- ALWAYS: the gate `check` job runs unconditionally — no job-level `if:` and no truthy job-level `continue-on-error` — so neither a gate step nor the enclosing job can skip or soft-pass the gate, per [spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([test](tests/test_ci_gate.compliance.l1.py))
- ALWAYS: every job this repository defines with `runs-on` declares an explicit `timeout-minutes` at or below the declared maximum, while a job calling a reusable workflow through `uses` declares none because the platform rejects the key there — an unbounded job never reports a conclusion, so it blocks no merge while holding a runner for the platform default, per [spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([test](tests/test_ci_gate.compliance.l1.py))
- ALWAYS: a gate step fails when the version the `spx` CLI the gate runs reports is below the marketplace's declared minimum spx version, the lowest version whose capabilities the shipped skills and their tests depend on, so a floor above what the pinned build reports fails the gate rather than shipping, per [spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([test](tests/test_spx_version_floor.compliance.l1.py))
- ALWAYS: the CI workflow provisions the `spx` CLI by building the `outcomeeng/spx` repository at one pinned commit, which is this repository's only pin on `outcomeeng/spx`, and never installs an `@outcomeeng/spx` release from the npm registry, so no gate run waits on an npm release, per [spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([test](tests/test_ci_gate.compliance.l1.py))
- ALWAYS: the marketplace's test-infrastructure implementation home is the top-level `outcomeeng_testing/` package — every tracked file under it lives outside `spx/` and outside any `tests/` directory, and no test-infrastructure module is tracked under `spx/` or within any `tests/` directory — the locally decidable subset of the placement rule in [`spx/31-outcomeeng.enabler/31-verification.enabler/31-test-verification.enabler/15-test-infrastructure.pdr.md`](spx/31-outcomeeng.enabler/31-verification.enabler/31-test-verification.enabler/15-test-infrastructure.pdr.md), checked against this repository's tracked files; `tests/` filename-shape conformance is covered separately by [`spx/15-test-language.adr.md`](spx/15-test-language.adr.md) and the validator under `spx/15-validation.enabler/` ([test](tests/test_infra_placement.compliance.l1.py))
- ALWAYS: an L3 test whose credentials are missing or invalid fails visibly, never skipping and never switching authentication mode, per [`spx/13-infrastructure.enabler/21-test-infrastructure.enabler/14-l3-tests.pdr.md`](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/14-l3-tests.pdr.md) ([audit])
