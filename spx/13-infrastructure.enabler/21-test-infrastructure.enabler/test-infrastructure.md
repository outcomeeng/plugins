# Test Infrastructure

PROVIDES a unified quality gate covering static analysis, type checking, linting, and test execution for all implementation code, plus the placement guarantee that the marketplace's own test-infrastructure implementation lives at its declared home
SO THAT the marketplace's Python scripts, validation tools, and test harnesses
CAN be verified for correctness before changes reach the main branch, with the test-infrastructure home kept outside `spx/` and outside any `tests/` directory

## Assertions

- Given a pytest run whose tests create temp files through `tempfile`, through `tmp_path`, and through a child process, when the run ends with a passing and a failing test, then the entries of the user temp folder equal the entries before the run
- ALWAYS: a pytest run creates its run root under `.spx/worktree/test-runs/` in its worktree, sets `TMPDIR` and Python's default temp directory to that root before its first test, and removes the root when the run ends, per [`spx/15-test-language.adr.md`](spx/15-test-language.adr.md)
- ALWAYS: a pytest run sets `GIT_CEILING_DIRECTORIES` to its run root before its first test, per [`spx/15-test-language.adr.md`](spx/15-test-language.adr.md)
- ALWAYS: before its first test, a pytest run removes every run root left under `.spx/worktree/test-runs/` in its own worktree and touches no path outside that worktree, per [`spx/15-test-language.adr.md`](spx/15-test-language.adr.md)
- NEVER: pytest keeps a `tmp_path` directory after its test ends, whether the test passed or failed, per [`spx/15-test-language.adr.md`](spx/15-test-language.adr.md)

### Compliance

- ALWAYS: GitHub Actions runs the full quality gate on `pull_request` and on push to `main` by invoking the `just check-full` gate recipe with the gate's toolchain provisioned at the project's declared Python version, never an inlined or filtered subset beyond the live-discovery selection [`spx/15-validation.enabler/65-gate.enabler/21-selected-gate.enabler/15-live-discovery.pdr.md`](spx/15-validation.enabler/65-gate.enabler/21-selected-gate.enabler/15-live-discovery.pdr.md) declares and never a soft-passed step, per [spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([test](tests/test_ci_gate.compliance.l1.py))
- ALWAYS: in every changeset that changes the CI workflow file, the codex-cli version the workflow pins equals the codex-cli version the maintainers' development host runs, and the pin carries no registry-update annotation, per [spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([audit])
- ALWAYS: the gate `check` job runs unconditionally — no job-level `if:` and no truthy job-level `continue-on-error` — so neither a gate step nor the enclosing job can skip or soft-pass the gate, per [spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([test](tests/test_ci_gate.compliance.l1.py))
- ALWAYS: every job this repository defines with `runs-on` declares an explicit `timeout-minutes` at or below the declared maximum, while a job calling a reusable workflow through `uses` declares none because the platform rejects the key there — an unbounded job never reports a conclusion, so it blocks no merge while holding a runner for the platform default, per [spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([test](tests/test_ci_gate.compliance.l1.py))
- ALWAYS: a gate step fails when the `@outcomeeng/spx` version pinned in the CI workflow is below the marketplace's declared minimum spx version — the lowest version whose capabilities the shipped skills and their tests depend on — so a dependency on an unpinned or unpublished spx capability fails the gate rather than shipping, per [spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md](spx/13-infrastructure.enabler/21-test-infrastructure.enabler/15-ci-gate.adr.md) ([test](tests/test_spx_version_floor.compliance.l1.py))
- ALWAYS: the marketplace's test-infrastructure implementation home is the top-level `outcomeeng_testing/` package — every tracked file under it lives outside `spx/` and outside any `tests/` directory, and no test-infrastructure module is tracked under `spx/` or within any `tests/` directory — the locally decidable subset of the placement rule in [`spx/31-outcomeeng.enabler/31-verification.enabler/31-test-verification.enabler/15-test-infrastructure.pdr.md`](spx/31-outcomeeng.enabler/31-verification.enabler/31-test-verification.enabler/15-test-infrastructure.pdr.md), checked against this repository's tracked files; `tests/` filename-shape conformance is covered separately by [`spx/15-test-language.adr.md`](spx/15-test-language.adr.md) and the validator under `spx/15-validation.enabler/` ([test](tests/test_infra_placement.compliance.l1.py))
