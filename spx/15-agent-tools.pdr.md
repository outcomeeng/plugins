# Agent Tools

A payload reaches a command through a file the agent writes in the scratch directory its harness names for the session, under a file name unique to that agent, and never through a heredoc, a pipe, or an inline form. A payload is any multi-line text, or any text carrying a code span, a quote, a shell metacharacter, or JSON; a path, a branch name, or an identifier is a command argument, never a payload. A tool takes the file through its own file argument, such as `gh --body-file <file>` or `git commit -F <file>`, or through an input redirect `<tool> < <file>`; an output redirect is no payload form. A request an agent sends to a skill's runner travels through a scratch file the same way, and the runner keeps its own pipes to the tools it drives. The agent never removes its payload files. The agent writes a payload file at the scratch directory's path exactly as the harness names it for the session, followed by the agent's unique file name, and never retypes, shortens, or reconstructs that directory. The agent writes no file without a task purpose — no dummy, probe, or placeholder file, and no file written only to learn whether a write succeeds — in any directory. Skills that instruct a `gh` call returning a collection also name its page bound in their own text.

## Rationale

A heredoc or pipe that carries code spans, shell text, or JSON triggers the dangerous-command guard, which refuses the command, and a single-quoted payload breaks on its first apostrophe. A session that meets such a refusal stops, departs from the skill, or drops the payload, so every pull-request body, Change draft, commit message, and mail record waits on a workaround. A file the agent writes with the harness's file-write tool carries any text unchanged and passes no shell parser, and every payload-bearing tool the skills call reads a file through a file argument or an input redirect.

The scratch directory the harness names for the session is the one location shared by every subagent the session launches and by no other session. `$TMPDIR` is shared by every session of the user, and a fixed path collides under concurrent runs, so neither is a payload location. A file name unique to the agent keeps two agents of one session from overwriting each other's payload. A harness that names no scratch directory has one fallback per environment, such as `$RUNNER_TEMP` on a hosted runner. The agent removes nothing it writes: the managed router forbids any command that deletes a file, the harness's garbage collection clears its scratch directory, and a harness without garbage collection keeps the file.

A retyped scratch directory differs from the harness's by one character as easily as by none, and a payload written there lands in a directory no session owns, beyond the reach of the harness's garbage collection and of every later reader of the payload.

A file with no task purpose serves no reader, and an agent cannot remove it under the managed router, so every such file stays behind for the operator to find.

GitHub's GraphQL budget belongs to the account, not to a session, so one unbounded paginated read spends the budget that every session on that account shares. A page bound written in the skill text keeps any one call from spending it, and a blocked result at the bound keeps a read that may be partial from passing as complete.

## Product properties

1. Agent-facing tool guidance names the scratch directory the harness names for the session as the payload location, and names one fallback per environment where a harness names none, such as `$RUNNER_TEMP` on a hosted runner.
2. Payload-bearing commands receive their payload from a file in that scratch directory under a name unique to the agent, through the tool's own file argument or an input redirect, and no skill teaches a heredoc, a pipe, or an inline form for a payload. A request to a skill's runner travels through a scratch file; the runner keeps its own pipes to the tools it drives.
3. A skill that instructs a `gh` call returning a collection — a `gh` list or search command, a `gh api` call with `--paginate` or to a collection endpoint — one whose response body is a JSON array — or a `gh api graphql` call reading a connection — names that call's page bound in its own text: a `--limit`, a page size with a page count, or a single page with its page size named; and a call whose result fills its bound returns a blocked result naming the bound, because a full result cannot show whether pages remain; a call ordered by recency that asks for its newest N names its N and reads a full result as complete. A single-object read such as `gh pr view` or `gh issue view`, and `gh pr checks`, is outside this property even when its result embeds a collection.
4. A payload file's directory is the scratch directory the harness names for the session, written exactly as the harness names it.
5. No agent writes a file without a task purpose, such as a dummy, probe, or placeholder file.

## Verification

### Audit

- ALWAYS: skills and agents that instruct Claude to call `spx`, `gh`, or another CLI with a payload pass it through a file Claude writes in the scratch directory the harness names for the session, under a file name unique to the agent, and name one fallback per environment where a harness names none ([audit])
- ALWAYS: payload-bearing tool guidance names the file form — the tool's own file argument such as `gh --body-file <file>` or `git commit -F <file>`, or an input redirect `<tool> < <file>` — and a request Claude sends to a skill's runner travels through a scratch file the same way; the guidance never directs Claude to remove a payload file ([audit])
- NEVER: payload-bearing tool guidance routes through a heredoc, a pipe, an inline form such as a quoted or `printf` argument, shell command substitution, or post-hoc text substitution to assemble or repair the body, and none directs a payload to a fixed path or to a shared `$TMPDIR` ([audit])
- NEVER: skill guidance instructs a `gh` call returning a collection — a `gh` list or search command, a `gh api` call with `--paginate` or to a collection endpoint — one whose response body is a JSON array — or a `gh api graphql` call reading a connection — without naming its page bound, including a list or search command that relies on the default limit of `gh`, `--paginate` without a page count, and a single-page collection read without a named page size, or reads a result that fills its page bound as complete, or stops on it without naming the bound, unless the call is ordered by recency and asks for its newest N ([audit])
- ALWAYS: payload-bearing tool guidance directs Claude to write each payload file at the scratch directory's path exactly as the harness names it for the session, never at a retyped, shortened, or reconstructed copy of that path ([audit])
- NEVER: skill or agent guidance directs Claude to write a file without a task purpose — a dummy, probe, or placeholder file, or a file written only to learn whether a write succeeds ([audit])
