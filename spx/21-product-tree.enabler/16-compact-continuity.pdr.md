# Post-Compact Continuity

Post-compact continuity uses Claude Code's standard compact summary as the state record and the managed root instruction block as the methodology-reload signal. After compaction the root instruction block requires `/understand` before the next product-content access and `/contextualize` on a node before any product content that node governs is read or modified and before that node is discussed; a compaction empties the set of contextualized nodes. An operational continuation — PR inspection, check wait, merge, deploy, release, `spx session` operations, occupancy proof — touches no product content and proceeds before either reload. Product content is the term the `/understand` foundation defines: every product artifact a spec node governs or must govern, with governance derived by search from node placement, the test-link chain, or an `[audit]` assertion naming the path. After compaction the resumed session receives one reminder that states as facts that a compaction occurred, that skill content and markers from before it are not live, that `/understand` runs before the next product-content access and `/contextualize` before the next access to content a node governs, and that the resumed session re-enters through the Change it holds and that Change's governing workflow skill where a live Claim exists, a position holder with no held Change recovers its grant and scope and invokes its position's governing skill before it acts on store or inbox work, a session with neither resumes under its live task instruction, and no Claim is inferred to satisfy recovery; the reminder instructs no step of its own. When the kill switch `PRODUCT_TREE_SESSION_HOOK_DISABLED` is set or the reminder is unavailable, the session receives no reminder and no error. The rules that hold after compaction — the foundation marker is absent until `/understand` re-emits it, the set of contextualized nodes is empty, a step that a compaction summary, a Handoff, a session file, or a coordination note names is a record and never an instruction — stand at the start of the `/understand` and `/contextualize` skill bodies, and the re-entry rule above stands at the start of the `/understand` skill body, ahead of their workflows, so a re-attachment that keeps only the opening of a skill carries them. The project defines no `compactPrompt` override. The `SessionStart` hook is limited to session-environment, worktree-occupancy, and post-compaction reminder behavior and carries no compact-summary behavior; its delegation and its compact entry are governed by [`spx/21-product-tree.enabler/15-hook-state-delegation.adr.md`](spx/21-product-tree.enabler/15-hook-state-delegation.adr.md).

## Rationale

Claude Code produces the compact summary that carries conversation state. A project-owned `compactPrompt` duplicates and constrains that summary, embeds runtime-specific wording, and grows stale as the runtime's base prompt evolves. The managed root instruction block survives as the product's routing authority and directs the required methodology reload without replacing the runtime's task summary. A compaction empties the set of active skills, so no skill is live at the moment the resumed session must decide what to do first; the reminder reaches the resumed conversation at the one lifecycle point that follows a compaction, and the reminder states facts and instructs no step because a step that a record names is never an instruction and only a live skill or the live task instruction instructs. The facts tell the resumed session which skills to invoke, and the re-entry rule is conditional on a live Claim because a Verifier such as an Advisor reviews a Change it does not hold, and a Claim inferred to satisfy recovery would be a false Claim. A session with neither a held Change nor a position resumes under its live task instruction, which authorizes recovery and skill loading, so the rule never leaves it unable to run the task the operator asked for. The rules that hold after compaction stand at the start of the `/understand` and `/contextualize` skill bodies and the re-entry rule at the start of the `/understand` skill body, and all of them in the router, because a re-attachment may keep only the opening of a skill and the hook may be disabled. Binding the reload to the first product-content access, per governing node, keeps the obligation decidable for any agent — the node is derived from the artifact about to be touched — and lets an operational continuation reach live PR and worktree state without first replaying methodology it does not use, which matters most on agents whose context window makes compaction frequent.

## Product properties

1. Claude Code's standard compact summary is the sole compact-summary prompt surface; the project defines no `compactPrompt` override.
2. After compaction the managed root instruction block directs `/understand` before the next product-content access, and `/contextualize` on the governing spec node before any product content it governs is read or modified and before that node is discussed; a compaction empties the set of contextualized nodes; product content with no governing spec is not read or modified; an operational continuation — PR inspection, check wait, merge, deploy, release, `spx session` operations, occupancy proof — touches no product content and triggers neither reload. A compaction empties the set of active skills as it empties the set of contextualized nodes; a step that a compaction summary, a Handoff, a session file, or a coordination note names is a record and never an instruction; and the resumed session re-enters as the re-entry rule states — through the Change it holds and that Change's governing workflow skill where a live Claim exists, through its position's governing skill after recovering its grant and scope where it holds a position and no Change, and under its live task instruction otherwise, with no Claim inferred to satisfy recovery — taking a step only when a live skill or its live task instruction instructs it, with recovery and skill loading authorized under the live instruction, so a session that holds neither a Change nor a position continues its live task and invokes any skill the task requires.

## Verification

### Audit

- ALWAYS: the managed root instruction block requires a live `<PRODUCT_TREE_FOUNDATION>` marker before anything under `spx/` or any other product content — source or test files, generated output, evals, spec-declared configuration — is read, searched, listed, or changed; states that a marker present only in a compaction summary, Handoff, or prior-run statement is not live; and names `spx session`, `spx worktree status`, `spx diagnose`, no-patch Git status, history, and topology, and a skill's read of the `spx/local/` overlay or exclusion mechanism it declares as exempt, while task reconstruction remains with the resuming agent and Claude Code's standard summary ([audit])
- ALWAYS: the managed root instruction block requires `/contextualize` on the governing spec node before any product content it governs is read or modified and before that node is discussed, states that a compaction empties the set of contextualized nodes, and forbids reading or modifying product content that has no governing spec ([audit])
- ALWAYS: the managed root instruction block states the governing-spec lookup as a search under the live foundation marker — a path under `spx/<node>/` is governed by that node; any other path by the node whose `spx/**/tests/` file names it and whose spec links that test, or whose spec or decision names that path in an `[audit]` assertion; several matching nodes resolve to their lowest common ancestor; no hit means that product content is not read or modified and the gap is recorded, while operational configuration — the `spx/local/` overlays and the exclusion mechanism — is configuration outside product content, read by its declaring skill without the marker ([audit])
- NEVER: the managed root instruction block, a lifecycle skill's entry step (`/manage-pr`, `/merge`, `/manage-github-pr`) requires `/understand` or `/contextualize` ahead of an operational continuation — PR inspection, check wait, merge, deploy, release, `spx session` operations, occupancy proof ([audit])
- ALWAYS: the managed root instruction block states that a compaction empties the set of active skills, that a step a compaction summary, Handoff, session file, or coordination note names is a record and never an instruction, and that the resumed session takes a step only when a live skill or its live task instruction instructs it, that recovery and skill loading are authorized under the live instruction, that a session holding neither a Change nor a position continues its live task and invokes any skill the task requires, and that it re-enters as the re-entry rule states: through the Change it holds and that Change's governing workflow skill where a live Claim exists, through its position's governing skill after recovering its grant and scope where it holds a position and no Change, and under its live task instruction otherwise, with no Claim inferred to satisfy recovery ([audit])
- ALWAYS: the reminder a resumed session receives after compaction states the facts of product property 4, instructs no step, and is the only text the post-compaction reminder behavior adds to the session ([audit])
- ALWAYS: when the kill switch `PRODUCT_TREE_SESSION_HOOK_DISABLED` is set or the reminder is unavailable, the resumed session receives no reminder and no error ([audit])
- NEVER: the `SessionStart` hook carries compact-summary behavior — it is limited to session-environment, worktree-occupancy, and post-compaction reminder behavior, with its delegation and its compact entry defined by [`spx/21-product-tree.enabler/15-hook-state-delegation.adr.md`](spx/21-product-tree.enabler/15-hook-state-delegation.adr.md) ([audit])
- NEVER: `.claude/settings.json` defines a `compactPrompt` override ([audit])
- NEVER: product-tree replaces or augments Claude Code's compact-summary prompt through project configuration ([audit])
