# Context Loading

PROVIDES deterministic loading of a target's Work Context in its Routine or its Authoring mode, each member at the view that mode names
SO THAT all implementation and authoring skills
CAN operate with complete, verified context before any work begins

## Assertions

### Audit: foundation references

- reference-triggers: The `/understand` skill states, for each reference under its `references/` directory, the condition under which a session reads that reference before it answers or decides, and the condition of `references/artifact-placement.md` covers every answer or decision about where an artifact goes. A reference with no stated condition, or an artifact-placement condition that leaves out an answer about where an artifact goes, fails the audit.
- marker-names-reads: The `<PRODUCT_TREE_FOUNDATION>` marker the `/understand` skill emits lists the path of each reference under its `references/` directory that the skill located, and names each of those references the session read before it emitted the marker, or none. A marker that lists a reference by name without its path, or names as read a reference the session did not read, fails the audit.

### Conformance

- The product-tree plugin package ships the foundation-resource manifest governed by [`spx/21-product-tree.enabler/18-context-loading.enabler/15-foundation-manifest.adr.md`](spx/21-product-tree.enabler/18-context-loading.enabler/15-foundation-manifest.adr.md) at `skills/understand/manifest.json` in every generated tree, naming exactly one core foundation document and the ordered references, templates, and examples catalogs as package-relative paths ([test](tests/test_foundation_manifest.conformance.l1.py))
- NEVER: the authored foundation-resource manifest and its generated-tree copies diverge, per [`spx/21-product-tree.enabler/18-context-loading.enabler/15-foundation-manifest.adr.md`](spx/21-product-tree.enabler/18-context-loading.enabler/15-foundation-manifest.adr.md) ([test](tests/test_foundation_manifest.conformance.l1.py))

### Compliance

- Package checks reject a shipped foundation-resource manifest whose declared paths do not all resolve, whose catalogs carry a duplicate path, or whose catalogs omit a shipped reference, template, or example file ([test](tests/test_foundation_manifest.compliance.l1.py))
- NEVER: the foundation-resource manifest carries content beyond paths and schema metadata, per [`spx/21-product-tree.enabler/18-context-loading.enabler/15-foundation-manifest.adr.md`](spx/21-product-tree.enabler/18-context-loading.enabler/15-foundation-manifest.adr.md) — package checks reject a content-bearing field ([test](tests/test_foundation_manifest.compliance.l1.py))
- ALWAYS: a foundation-resource manifest shape change within a schema version is additive, and a breaking shape change increments `schema_version`, per [`spx/21-product-tree.enabler/18-context-loading.enabler/15-foundation-manifest.adr.md`](spx/21-product-tree.enabler/18-context-loading.enabler/15-foundation-manifest.adr.md) ([audit])
- NEVER: the `/contextualize` skill runs `/sync-base`, fetches, rebases, or otherwise moves the checkout — it reads the checkout as it stands, so a Verifier's context load leaves the head it judges in place ([audit])
- ALWAYS: the `/contextualize` skill presents a context-grounded answer only after it emits the `<PRODUCT_TREE_CONTEXT>` marker for that target; loading the skill or reading a pre-compaction summary supplies no context ([audit])
- ALWAYS: before any filesystem lookup, the `/contextualize` skill accepts a target only when it is the canonical product-root address `spx/` or a full repository-relative node address whose segments each match `{index}-{slug}.{kind}` for one of the seven kinds, or the prior `enabler` and `outcome` forms a tree authored under a 3.x version still carries; it rejects a missing target, traversal segment, empty segment, or malformed node segment before deriving the read-set ([audit])
- NEVER: a skill or generated instruction surface derives the methodology version from a plugin distribution version, a proposal document, a changelog, or prose — the declaration the SPX CLI resolves is the only source ([audit])
- ALWAYS: the `/contextualize` skill aborts with the missing file path and remediation guidance when a required ancestor spec is absent ([audit])
- ALWAYS: when the canonical product-root target `spx/` addresses a tree with one product document and no node directories, the `/contextualize` skill emits the product-root context manifest with `bootstrap=true`; a missing node target aborts, and new-node authoring contextualizes the existing parent ([audit])
- ALWAYS: the `/contextualize` skill emits node, ADR, PDR, test, and note references as full paths from `spx/` — bare names and bare decision filenames are ambiguous because numeric prefixes are sibling-local ([audit])
- ALWAYS: the `/contextualize` skill emits lifecycle continuation state in the context manifest — local lifecycle overlays read, default-branch completion boundary, the governed next workflow, a progress verdict rule, and a continuation action when a changeset is destined for the default branch — so context loading carries the merge obligation into the workflow that follows ([audit])
- ALWAYS: the `/contextualize` skill treats the `PRODUCT_TREE_FOUNDATION` marker as absent after every compaction event until `/understand` re-emits it in the resuming conversation ([audit])
- foundation-gate: ALWAYS: the `/contextualize` skill requires a live `PRODUCT_TREE_FOUNDATION` marker before direct filesystem access to any path under `spx/`, or before reading, searching, listing, or changing any other product content — source or test files, generated output, evals, spec-declared configuration; operational-state commands under `spx session`, `spx worktree status`, `spx diagnose`, and no-patch Git status, history, and topology, and a skill's read of the `spx/local/` overlay it declares, remain available without the marker until their output is followed into product content ([audit])
- ALWAYS: the `/understand` skill loads the truth hierarchy, node model, artifact placement, assertion model, ordering model, verification model — with malleability, state, and projection — change model, and imperfection protocol from one eager payload without mandatory secondary reference reads; operational references, templates, examples, and local overlays remain separately discoverable ([audit])
- ALWAYS: the `/understand` skill reads the root instruction file from disk only when the live conversation does not already carry it complete — a harness that injects the whole file satisfies the step, and a truncated or absent injection requires the read ([audit])
- NEVER: the `/contextualize` skill proceeds with partial context — it aborts if any required document is missing ([audit])
- NEVER: the `/contextualize` skill adds a cited governance decision to the read-set from `PLAN.md`, `ISSUES.md`, or any other note prose ([audit])
- NEVER: the `/contextualize` skill accepts a `PRODUCT_TREE_FOUNDATION` mention in a compaction summary, Handoff, prior-run description, or statement that `/understand` ran as evidence that the marker is live ([audit])
- NEVER: the `/contextualize` skill infers implementation state from test imports — implementation state is unknown unless another workflow establishes it ([audit])

### Audit: work context

- work-context-mode: The `/contextualize` skill loads its target's Work Context in the mode its caller names, Routine for Specify, Implement, and a code, test, or evidence Audit, and Authoring for Declare, Refinement, decomposition, and a spec or Decision Record Audit, as `product-tree/context.md` of a declared methodology version at or after 4.0 states it, and its context manifest names the mode and each member with its view; a call that names no mode loads Authoring mode, whose members hold every member of Routine mode, and its manifest names Authoring as the mode taken.
- work-context-members: In either mode the `/contextualize` skill loads the Product spec and every ancestor spec at Complete; for the target and each ancestor, each lower-Index sibling spec at Declaration; every governing Decision Record at Complete, never filtered by title: the target's own, each ancestor record indexed below the child the path continues through, and each cross-subtree and transitive citation; every `ISSUES.md` of the target and its ancestors; the target spec at Complete with its Outcome record and its Knowledge `index.md`; every contract file a member spec links; and every implementation file the target or its Variants pin.
- ancestor-records-excluded: NEVER: the `/contextualize` skill loads an ancestor Decision Record indexed at or above the child the path continues through, unless a member file cites it.
- routine-peers: In Routine mode the `/contextualize` skill lists same-Index and higher-Index siblings by directory entry, reads no file of theirs, and loads no immediate child, deeper descendant, test, eval, or probe file, and no other Node's Outcome record or Knowledge.
- authoring-peers: In Authoring mode the `/contextualize` skill adds the target's immediate children, Variants included, at Declaration, and its same-Index and higher-Index siblings at Opening, or at Declaration when the work scopes a provider's mandate against its direct consumers, and loads no deeper descendant, test, eval, or probe file, and no other Node's Outcome record or Knowledge.
- member-views: The `/contextualize` skill gives each member at its view. Opening: the title and role Opening for an output Node spec, the title and optional identity paragraph for a `.product` spec, and the title and Opening for a Decision Record, front matter left out. Declaration: the Opening plus every heading and every shortened Assertion or rule, Scenarios keeping bare slugs without Given, When, or Then lines, Probes keeping their sentence, test, eval, and probe links unwrapped to bare slugs while contract links stay intact, and Mapping and Evaluate subsections keeping their sentence and case slugs without table bodies; for a `.product` spec, the full body without front matter. Complete: the whole file verbatim, including YAML front matter, artifact links, Scenario steps, and full tables.
- manifest-determinism: The `/contextualize` skill produces the same context manifest for the same tree contents, target, and mode.
- enumeration-source: The `/contextualize` skill derives the Work Context as [`spx/21-product-tree.enabler/18-context-loading.enabler/13-context-enumeration.adr.md`](spx/21-product-tree.enabler/18-context-loading.enabler/13-context-enumeration.adr.md) decides, reads the instruction files and the lifecycle overlay `spx/local/merging.md` outside the read order, and lists the other local overlays without reading them.
- methodology-source: The `/contextualize` context manifest states the methodology source and exact version the repository follows, from the `methodology` block of `spx config show --json`, so every session applies the declared methodology and its rules for the node under work, per [`spx/21-product-tree.enabler/18-context-loading.enabler/13-context-enumeration.adr.md`](spx/21-product-tree.enabler/18-context-loading.enabler/13-context-enumeration.adr.md).
