# Verify Skill

PROVIDES verification-type selection and evidence-work orchestration from one assertion or canonical product-tree scope
SO THAT authoring, applying, architecture, test-auditing, and evidence-maintenance workflows
CAN route every assertion to test, evaluate, probe, or audit before a specialist chooses lower-level evidence details

## Assertions

### Evaluate: [routing](evals/routing/eval.toml)

`/verify` receives one assertion from a fixture spec and the catalogue of available specialists the row names, classifies the assertion by the verdict its real subject can produce, and reports one result, whose `verification_type`, `specialist`, `status` and `evidence_shape` the eval compares with the row's expectation.

### Audit: routing workflow

- decision-rule-headings: `/verify` takes a decision rule's current verification type from the group heading it stands under, `Test.Scenario`, `Test.Conformance`, `Test.Property`, `Test.Compliance` or `Audit`, or from its own `Test.Mapping:` or `Evaluate:` subsection, reads no tag on the rule, and blocks a decision rule that carries a tag with reason `unsupported-tag-shape`.
- decision-rule-placement: `/verify` moves a decision rule it routes under the group heading of the selected verification type, or into its own `Test.Mapping:` or `Evaluate:` subsection, and writes no tag on it; that move is the rule's provisional placement.
- keeps-change-heading: `/verify` routes an Assertion under the group heading its Change states and writes no tag; the Assertion's slug gains its evidence link only once that evidence exists.
- typing-after-selection: Test assertion typing occurs only after test is selected; a test assertion type chosen before the verification type fails the audit.
- invoked-for-selection: Every workflow that delegates verification-type selection invokes `/verify` rather than a type-specific specialist.
- no-duplicated-specialist: `/verify` duplicates no test assertion typing, language expression, eval producer specialization, or audit judgment.
- foreground-load-gated: A load-gated command `/verify` runs executes in the foreground, and `/verify` reports its result only after every such command has exited.

### Audit: verify result

- result-shape: `/verify` emits one structured result per spec assertion or decision rule, carrying `subject`, `verification_type`, `specialist`, `status`, `evidence_shape` and `reason`; `subject` carries the source path, the line the subject holds there after the run, and a text that is null exactly when `reason` is `unsupported-tag-shape` and otherwise the subject's exact text; `status` is one of `routed`, `capability-required` or `blocked`; a set `evidence_shape` is `path-bearing` for a spec test, eval or probe assertion, `pathless` for a spec audit assertion, and `requirement` for a decision rule, and a `capability-required` result keeps the shape of its selected route; a result that lacks a field, or a `routed` or `capability-required` result that names no verification type, specialist or evidence shape, fails the audit.
- report-from-result: `/verify` renders its human report table from its structured results alone; a row whose Subject column lacks the subject's path and line, a null value shown other than as an em dash, or a row that disagrees with its result fails the audit.
- verify-rollback: A decision-rule route that ends other than `routed` restores that rule's provisional placement, and a run whose rule keeps that placement after such a route fails the audit; a closing `spx validation markdown` that exits non-zero restores every durable edit the invocation made and turns every formerly routed result to `capability-required`, keeping its selected verification type, specialist and evidence shape and naming the failed validation in `reason`, and a run that keeps any durable edit it made, or leaves any formerly routed result `routed`, after that failure fails the audit; in both failures every edit made before the run stays unchanged, and a run that alters one fails the audit.
- cli-state-readout: `/verify` selects test for an assertion about deterministic CLI state an LLM only reads out for an independent comparison, and evaluate for an assertion about model-generated behavior a CLI exposes; a selection the other way fails the audit.
