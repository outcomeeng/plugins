# Reviewing Changes

PROVIDES a verification skill that reviews a working changeset through a single shipped runner, records the review as a sealed `spx journal --type review` run, and returns the raw run token
SO THAT local reviewers, wrapper agents, and hosted integrations share one durable review record
CAN project the sealed journal into the surface they own without duplicating review rendering inside the skill

## Assertions

### Scenarios

- Given `SPX_VERIFY_BASE_REF` set in the environment, `review_run.py start` uses that scope, computes the review-input bundle, opens the review journal, appends the scope-entered event, and returns run state including `runToken`, `statePath`, `diffPath`, `manifestPath`, and `changedFiles` ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given no `SPX_VERIFY_BASE_REF` AND `git symbolic-ref refs/remotes/origin/HEAD` resolves, `compute_diff.py` uses that symbolic ref reduced to its remote-tracking form `origin/<base>` as `base_ref`, so a stale local branch ref cannot widen the diff ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given no `SPX_VERIFY_BASE_REF` AND no `refs/remotes/origin/HEAD` symbolic ref, `compute_diff.py` exits non-zero with a stderr message naming both sources so the operator can identify which to populate ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given `SPX_VERIFY_HEAD_REF` set in the environment, `compute_diff.py` uses that value as `head_ref` instead of the default `HEAD` ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given no `SPX_VERIFY_HEAD_REF`, `compute_diff.py` uses the literal `HEAD` as `head_ref` — `head_ref` has a default; `base_ref` does not ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given committed feature changes, staged changes, unstaged changes, and untracked files in the working tree, `compute_diff.py` includes all four as labeled sections in the review input so local review sees every change the next push or commit can carry ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given `compute_diff.py --bundle-dir <dir>`, the script writes a caller-owned scratch review-input bundle outside the git worktree containing `diff.md` and `manifest.json`, and stdout reports the two paths plus the diff byte count and section count so the reviewer can read the diff with random access while durable review state remains journal-only ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given one raised finding, `review_run.py append-finding` appends one finding-reported event through the journal and `review_run.py finish` appends a terminal run-completed event carrying review status and finding counts, seals the run, removes runner-owned scratch state, and returns only `runToken` ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given `review_run.py finish` is called before every changed file that is neither a declared generated extent nor a pure rename has a scope-advanced event or an unread mark, `finish` exits non-zero and names the unexamined files in stderr so an incomplete review cannot be sealed ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given no `spx/local/generated-sources.toml` committed at the scope's base ref, `review_run.py start` lists no declared generated extent and treats every changed file as an ordinary changed file ([test](tests/test_review_run_generated_extents.scenario.l2.py))
- Given a changeset whose changed files include a file that a relation's whole-file output pattern matches, `review_run.py finish` records the file on the run-completed event as skipped by declaration together with its relation's regenerate command, appends no scope-advanced event and no unread mark for it, and seals a run whose only unexamined files are declared generated extents by its findings rather than as `failed` ([test](tests/test_review_run_generated_extents.scenario.l2.py))
- Given a changeset that changes a relation's declared source or generator together with a file that relation's whole-file output pattern matches, `review_run.py start` flags that relation in the returned run state so the reviewer judges the generator change with the extents as evidence it may read, and `review_run.py finish` still requires neither a scope-advanced event nor an unread mark for the extent ([test](tests/test_review_run_generated_extents.scenario.l2.py))
- Given a repository whose `spx/local/generated-sources.toml` differs between the scope's base commit and the head or the working tree, `review_run.py start` lists in the run state the relations and extents of the declaration as committed at the scope's base ref, so an edit at the head or in the working tree changes neither the relations nor the extents the run state lists; when the declaration is itself a changed path, the scenario for a changed declaration governs exemption, flagging every relation and exempting nothing ([test](tests/test_review_run_declaration_base.scenario.l2.py))
- Given a changeset whose changed paths include `spx/local/generated-sources.toml`, `review_run.py start` exempts no changed file from coverage by declaration, flags every relation in the returned run state with the changed declaration as the reason, and `review_run.py finish` names the changed declaration on the run-completed event ([test](tests/test_review_run_declaration_changed.scenario.l2.py))
- Given a changeset that renames a file with git rename detection, the changed-file set lists the file once under its new path with its former path recorded, and `review_run.py finish` records a rename with unchanged content on the run-completed event as renamed without content change, with no scope-advanced event and no unread mark for it ([test](tests/test_review_run_renames.scenario.l2.py))
- Given a changeset that renames a file and changes its content, `review_run.py finish` requires a scope-advanced event or an unread mark for the file under its new path, exactly as for any other changed file ([test](tests/test_review_run_renames.scenario.l2.py))
- Given `review_run.py finish --unread-file <path>` naming a file that lists one changed path per line, `finish` marks each listed path as unread exactly as one `--unread` argument per path does, so an unread set of any size reaches the runner through one argument ([test](tests/test_review_run_unread_file.scenario.l2.py))
- Given a conforming review-result document, `review_result.parse_json` returns a `ReviewResult` dataclass ([test](tests/test_review_result.scenario.l1.py))
- Given a document that omits a required key, `review_result.parse_json` raises `ReviewResultValidationError` naming the missing key ([test](tests/test_review_result.scenario.l1.py))
- Given a finding whose `severity` or `concern` is outside its enum, `review_result.parse_json` raises `ReviewResultValidationError` naming the offending value and the allowed set ([test](tests/test_review_result.scenario.l1.py))
- `review_result.to_json_dict` and `review_result.from_json_dict` round-trip a `ReviewResult` instance without loss ([test](tests/test_review_result.scenario.l1.py))

### Mappings

- `Severity` enum members map to the wire values `blocking`, `debt` ([test](tests/test_review_result.mapping.l1.py))
- `Concern` enum members map to exactly the five wire values `consistency`, `security`, `performance`, `evidence`, `architecture` ([test](tests/test_review_result.mapping.l1.py))
- Review severities map into the shared run-journal projection as `blocking` -> `reject` and `debt` -> `warning`; the projection then owns terminal status rollup from the sealed prefix ([test](tests/test_review_journal_emit.mapping.l1.py))
- `review_run.py finish` maps finding severities into terminal review counts on the run-completed event: rejecting findings increment `blocking`, warning findings increment `debt` ([test](tests/test_skill_orchestration.mapping.l2.py))
- `review_run.py append-finding` maps a finding payload's optional `unit` and `tracked` fields onto the finding-reported event, and `review_run.py finish` counts a `tracked` `debt` finding toward `debt` ([test](tests/test_skill_orchestration.mapping.l2.py))
- `review_run.py start` reads the declaration `spx/local/generated-sources.toml` as committed at the scope's base ref (`git show <base>:spx/local/generated-sources.toml`), a declaration absent at the base yielding no extent, and maps each changed file that a relation's whole-file output pattern matches to a declared generated extent, listed in the manifest and the returned run state under its relation together with the relation's sources, generator, and regenerate command ([test](tests/test_review_run_generated_extents.mapping.l2.py))
- `journal_emit.py render` is a helper projection over sealed journal events for compatibility tests, while the live skill path returns only the run token ([test](tests/test_review_journal_emit.mapping.l1.py))

### Properties

- For every `ReviewResult` instance, `from_json_dict(to_json_dict(r)) == r` — serialization is lossless ([test](tests/test_review_result.property.l1.py))

### Compliance

- ALWAYS: the review skill advances a changed file's scope only after reading the file, and marks every changed file it does not read as unread before it finishes — except a declared generated extent and a pure rename, which the runner accounts for without a scope-advanced event or an unread mark — per [`spx/21-product-tree.enabler/16-verification.enabler/13-run-journal.adr.md`](spx/21-product-tree.enabler/16-verification.enabler/13-run-journal.adr.md) ([audit])
- ALWAYS: a review whose branch value names a commit rather than a branch records the checked-out branch as its branch identity and slug, per [`spx/21-product-tree.enabler/16-verification.enabler/13-run-journal.adr.md`](spx/21-product-tree.enabler/16-verification.enabler/13-run-journal.adr.md) ([test](tests/test_review_branch_identity.compliance.l2.py))
- NEVER: the reviewer agent exports a commit as the branch identity for a commit-range input, per [`spx/21-product-tree.enabler/16-verification.enabler/13-run-journal.adr.md`](spx/21-product-tree.enabler/16-verification.enabler/13-run-journal.adr.md) ([audit])
- ALWAYS: the `review-changes` skill writes each finding payload with the file-write tool to a file in the scratch directory the harness names for the session, copying that directory into the finding path character for character; when the file-write result reports a path the scratch directory does not contain by whole path components, it stops before `append-finding`, naming the reported path; it passes `append-finding` the path exactly as the file-write result reports it, written out literally; and when `append-finding` exits nonzero with a diagnostic that names the finding file absent, it runs `append-finding` once more with the path copied from the file-write result and, on a second failure, stops and reports the exit, the stderr and the run token; no finding path is retyped from memory ([audit])
- ALWAYS: `review_run.py start` relays the shared resolver's stale-base refusal for a head behind the fetched `origin/<base>` tip — the dedicated exit code and the diagnostic, with no run state — before it opens a journal, so no review run records a tree that cannot merge ([test](tests/test_stale_base_relay.compliance.l1.py))
- ALWAYS: `review_run.py start` reports a base it cannot fetch or resolve as one stderr diagnostic line carrying git's own message and a nonzero exit, with no run state and no traceback ([test](tests/test_stale_base_relay.compliance.l1.py))
- NEVER: `review_run.py start` treats a region-bounded output of a relation — a `file` with `begin` and `end` markers — as a declared generated extent; the file stays an ordinary changed file that requires a scope-advanced event or an unread mark ([test](tests/test_review_run_generated_extents.compliance.l2.py))
- ALWAYS: the `review_result.py` policy module declares `SCHEMA_VERSION`, frozen `Finding` and `ReviewResult` dataclasses, and the `Severity` and `Concern` enums — the canonical review-result schema lives in one Python module ([audit])
- ALWAYS: `review_result.py` takes the agent tokens of its generated-tree citation candidates from the data file the build renders beside it, and declares no agent token of its own
- NEVER: the review-result schema carries a `summary`, acknowledgement, `decision`, or verdict field — a review produces findings only; each consumer acts on a `blocking` finding by validity and phase and on a `debt` finding by its ruling, per [`spx/15-merging.pdr.md`](spx/15-merging.pdr.md) ([audit])
- ALWAYS: the review prompt instructs the reviewer to review the whole diff and to treat any caller-supplied scope, severity pre-filter, or emphasis as non-authoritative ([audit])
- ALWAYS: the review prompt carries one domain-neutral `<adversarial_probes>` section the reviewer applies before treating a reviewed unit as clean — a counterexample probe that classifies constructed domain members through a universal, totality, or partition claim exactly as written; a conjunct-completeness probe that aligns derived, restated, or rendered text condition by condition with its cited source; a definite-description probe that resolves every newly introduced description or category name to its declaring owner in the loaded truth chain; and a blast-radius probe that follows a changed governing declaration into its consumers, checks the changed files themselves for retired terminology, and verifies closure claims against the resulting files — each observation attempted against its strongest plausible refutation before it becomes a finding, and each probe encoding no execution level, runner name, or node vocabulary ([audit])
- ALWAYS: the review scope extends from changed files to every unchanged consumer of a changed governing declaration — a full-path citation of the changed decision or spec, a rendering or generated output the repository's declared generated-source relations derive from it, a consumer or specialization the loaded governance names, or a sibling specialization under a changed superset rule — discovered through read-only search bounded to those declared relationships and never through an unbounded repository-wide semantic search, with a contradiction reported as a `consistency` finding at the consumer's location ([audit])
- ALWAYS: consumer discovery leaves the journal's scope coverage on the changed-file set — an inspected unchanged consumer is a finding site, never an `append-scope` unit — so a probe or consumer inspection that finds no defect appends no event and the finding-only journal contract holds ([audit])
- ALWAYS: the `review-changes` skill prose loads only the bundled prompt at `${CLAUDE_SKILL_DIR}/references/review-prompt.md`; repository-root `REVIEW.md`, `REVIEW.example.md`, and other review prompt files are not review context ([audit])
- ALWAYS: scripts under `plugins/product-tree/skills/review-changes/scripts/` write no durable review state directly; `compute_diff.py` may write only the caller-owned scratch review-input bundle files, and `review_run.py` may write and remove runner-owned scratch state ([test](tests/test_reviewing_changes.compliance.l1.py))
- ALWAYS: the swappable review prompt template lives at `plugins/product-tree/skills/review-changes/references/review-prompt.md` and the skill prose loads it via `${CLAUDE_SKILL_DIR}/references/review-prompt.md` ([audit])
- ALWAYS: `Finding.rule` is a non-empty string whose form is a path-style citation into an existing rule in the product-tree or skill ecosystem, from one of the declared citation families — `spx/<path>:<MUST\|NEVER\|ALWAYS\|SCENARIO\|MAPPING\|CONFORMANCE\|PROPERTY\|AUDIT>:<n>`, a path to a product-tree ADR/PDR, `plugins/<plugin>/skills/<skill>/SKILL.md:<rule-slug>`, `AGENTS.md:<rule-slug>`, or `CLAUDE.md:<rule-slug>` ([test](tests/test_review_result.mapping.l1.py))
- NEVER: `Finding.rule` is a free-form description, a required-action string, a repository-root review policy citation, a tracking-location string, a relative `SKILL.md:<rule-slug>` citation, or a citation whose file, assertion, or rule slug does not exist — the parser rejects each and names the offending value ([test](tests/test_review_result.compliance.l1.py))
- ALWAYS: `Finding.rule` cites a rule that actually exists at the referenced location — the review prompt instructs the model to populate `rule` from rules declared in the loaded context, never to invent a citation ([audit])
- ALWAYS: the wrapper agent invokes the `review-changes` skill and the skill uses only `review_run.py` as its command surface ([audit])
- ALWAYS: the verification skill emits a `blocking` finding asserting absence of a file or fact only when the diff itself contains the deletion or omission — the verification skill does not hallucinate missing artifacts it cannot observe ([audit])
- ALWAYS: finding `severity` matches the rubric in `plugins/product-tree/skills/review-changes/references/review-prompt.md` — `blocking` for merge-safety defects, `debt` for real defects that do not jeopardize merge safety ([audit])
- ALWAYS: the review prompt instructs the Reviewer to read the `ISSUES.md` of each governing node of the changed files, to record with each finding its entry key — the path of the file it names, the label of the unit that encloses it, and its rule citation — and to label `TRACKED` each `debt` finding whose entry key an entry heading in that `ISSUES.md` carries ([audit])
- ALWAYS: each pass against a given changeset surfaces every finding the changeset exhibits in that single pass — there is no cross-pass continuity, and a finding missed on this pass has no second chance unless the diff itself changes ([audit])
- ALWAYS: the review prompt fixes the criteria of the `evidence` concern, so two passes over an unchanged subject — the same unit text under the same governing context, at any head — raise the same `evidence` finding or none, and no pass reads another pass's verdict to reach its own ([audit:same-evidence-verdict])
- NEVER: a review raises a finding on the sole ground that an eval's `history.jsonl` records a run on an earlier commit than the head — evaluate runs in CI only on an operator's dispatch, so the history file is a trend record and never a result the changeset owes, per [`spx/31-outcomeeng.enabler/31-verification.enabler/14-verification.pdr.md`](spx/31-outcomeeng.enabler/31-verification.enabler/14-verification.pdr.md) ([audit:stale-eval-history])
- ALWAYS: known-clean diffs yield zero `blocking` findings and known-broken diffs yield at least one `blocking` finding ([audit])
- NEVER: any script under `plugins/product-tree/skills/review-changes/scripts/` imports a third-party package, depends on `uv` at runtime, or imports any `outcomeeng_*` module — stdlib only per the Plugin Portability Constraints in `AGENTS.md` ([test](tests/test_reviewing_changes.compliance.l1.py))
- NEVER: the wrapper agent writes review artifacts outside `spx journal`; durable review state is the sealed review journal prefix ([audit])
- NEVER: the review prompt is embedded inside `SKILL.md` or any script — the prompt is one standalone markdown file at the declared reference path so swapping the prompt does not require touching code ([audit])
- NEVER: repository-root `REVIEW.md` or `REVIEW.example.md` exists in this product checkout — local and CI review use the hidden prompt shipped by the `review-changes` skill ([audit])
- NEVER: the live `review-changes` skill path renders, summarizes, counts, or restates findings for the caller; caller-facing output is the raw run token ([test](tests/test_skill_orchestration.conformance.l2.py))
