# Sync Base

PROVIDES automatic base synchronization with authorized checkpoint recovery, a deterministic Git primitive, and a completed currency result
SO THAT context loading, the merge lifecycle, and session pickup
CAN read product truth, verify, and integrate against a current base without re-deriving base operations or surfacing a routine rebase as an operator decision

## Assertions

### Scenarios

These assertions exercise the bundled synchronization primitive. The `/sync-base` skill owns recovery from its intermediate results.

- Given a branch whose HEAD is behind its fetched base, when the synchronization primitive runs, then the branch's own commits are replayed onto `origin/<base>` and the changes already merged into the base are present in the working tree ([test](tests/test_sync_base.scenario.l1.py))
- Given a branch already current with its fetched base, when the synchronization primitive runs, then it performs no rebase and reports the branch already current ([test](tests/test_sync_base.scenario.l1.py))
- Given a rebase that conflicts and cannot be resolved autonomously, when the synchronization primitive runs, then it stops with the rebase state active and reports structured conflict details — summary, conflicted paths, base and branch git facts, git's conflict text, and operator options to inspect, continue, or abort — rather than aborting the rebase or emitting an opaque action token ([test](tests/test_sync_base.scenario.l1.py))
- Given a behind-base branch whose working tree has uncommitted changes to tracked files, when the synchronization primitive runs, then it reports the distinct `dirty_tree` outcome without attempting the rebase, leaving the working tree untouched and emitting no conflict details — the skill owns checkpoint recovery and retry ([test](tests/test_sync_base.scenario.l1.py))
- Given a behind-base branch whose only working-tree change is a non-colliding untracked file, when the synchronization primitive runs, then it rebases normally rather than reporting `dirty_tree` — a non-colliding untracked file does not block a rebase and is not a dirty tree ([test](tests/test_sync_base.scenario.l1.py))
- Given a base ref that does not resolve, when the synchronization primitive runs, then it reports a hard git failure rather than rebasing onto an unresolved target ([test](tests/test_sync_base.scenario.l1.py))
- Given a clean detached HEAD whose commit is an ancestor of the fetched base and is behind it, when the synchronization primitive runs, then it advances the worktree to the `origin/<base>` tip and reports `rebased`, with the base advance present in the working tree — a parked pool worktree is brought current rather than waved through on a stale commit ([test](tests/test_sync_base.scenario.l1.py))
- Given a clean detached HEAD already at the fetched base tip, when the synchronization primitive runs, then it performs no advance and reports `already_current` ([test](tests/test_sync_base.scenario.l1.py))
- Given a detached HEAD behind the base whose working tree has uncommitted changes to tracked files, when the synchronization primitive runs, then it reports the `dirty_tree` outcome without advancing, leaving the working tree untouched — the skill owns checkpoint recovery and retry ([test](tests/test_sync_base.scenario.l1.py))
- Given a detached HEAD that has diverged from the base — carrying commits the base lacks — when the synchronization primitive runs, then it reports a hard git failure rather than advancing, because advancing would orphan those commits and a detached HEAD has no branch to rebase them onto ([test](tests/test_sync_base.scenario.l1.py))
- Given a detached HEAD with no resolvable remote base, when the synchronization primitive runs, then it reports a hard git failure rather than attempting to advance ([test](tests/test_sync_base.scenario.l1.py))
- Given a clean detached HEAD behind the base whose only working-tree change is a non-colliding untracked file, when the synchronization primitive runs, then it advances the worktree rather than reporting `dirty_tree` — a non-colliding untracked file does not block the advance and is not a dirty tree ([test](tests/test_sync_base.scenario.l1.py))
- Given a caller-supplied base branch name, when the synchronization primitive runs, then it synchronizes onto that base's remote-tracking ref `origin/<base>` rather than the `origin/HEAD` default — so a stacked changeset rebases onto its actual base ([test](tests/test_sync_base.scenario.l1.py))
- Given a caller-supplied base branch name that is not the default branch, when the synchronization primitive completes, then the synchronized branch carries a stack record naming that base and the tip it now sits on ([test](tests/test_sync_base_stack.scenario.l1.py))
- Given a branch carrying a stack record whose predecessor merged, when the synchronization primitive runs with `--base` naming the default branch, then it replays only the commits above the recorded tip onto `origin/<default>`, reports the recorded tip as the proof's `old_base_oid`, and removes the record ([test](tests/test_sync_base_stack.scenario.l1.py))
- Given a branch carrying a stack record whose recorded tip is no longer an ancestor of the branch because an operator completed a conflicted restack by hand, when the synchronization primitive runs, then it reports the branch current with its target and removes or rewrites the record rather than failing ([test](tests/test_sync_base_stack.scenario.l1.py))
- Given a branch behind its base and a second local branch stacked on that branch's tip, when the synchronization primitive rebases the first branch, then the second branch carries a stack record naming the rebased branch and its pre-rebase tip ([test](tests/test_sync_base_stack.scenario.l1.py))
- Given a chain of three stacked branches whose third branch records the second as its predecessor, when the synchronization primitive rebases the first branch, then the second branch records the first and the third branch's record still names the second ([test](tests/test_sync_base_stack.scenario.l1.py))
- Given a branch carrying a stack record whose predecessor is open on origin, contains the recorded tip, and has advanced, when the synchronization primitive runs without a caller-supplied base, then it rebases onto the predecessor's remote-tracking ref and the record's tip becomes the predecessor's tip ([test](tests/test_sync_base_stack.scenario.l1.py))
- Given a branch carrying a stack record whose predecessor was rewritten and force-pushed while still open on origin, when the synchronization primitive runs, then it replays only the commits above the recorded tip onto the predecessor's remote-tracking ref, reports the recorded tip as the proof's `old_base_oid`, and the record's tip becomes the predecessor's tip ([test](tests/test_sync_base_stack.scenario.l1.py))
- Given a branch carrying a stack record whose predecessor was rewritten locally and is absent from origin while its local branch survives unmerged, when the synchronization primitive runs, then it replays only the commits above the recorded tip onto the local predecessor and the record's tip becomes that branch's tip ([test](tests/test_sync_base_stack.scenario.l1.py))
- Given a branch carrying a stack record whose predecessor was rewritten, merged into the default branch, and deleted from origin, when the synchronization primitive runs, then it replays only the commits above the recorded tip onto `origin/<default>`, reports `rebased` with the recorded tip as the proof's `old_base_oid`, and removes the record ([test](tests/test_sync_base_stack.scenario.l1.py))
- Given a branch with no stack record sitting on the pushed tip of a surviving local predecessor that forked from the default branch, when the synchronization primitive runs without a caller-supplied base, then it records that predecessor with the fork as the tip and synchronizes onto the predecessor's remote-tracking ref ([test](tests/test_sync_base_stack.scenario.l1.py))
- Given a rebase that conflicts on a branch with no stack record and no derivable predecessor, when the synchronization primitive stops, then its operator options include the restack form `git rebase --onto origin/<base> <fork>` ([test](tests/test_sync_base_stack.scenario.l1.py))
- Given a clean rebase whose base advance changed only files the branch does not touch, when the synchronization primitive runs, then the readiness-preservation proof reports no path overlap between the base delta and the branch's changed paths and an unchanged branch patch identity — the signal a caller reads to reuse a prior local review ([test](tests/test_sync_base_preservation.scenario.l1.py))
- Given a clean rebase whose base advance changed a file the branch also changed, when the synchronization primitive runs, then the readiness-preservation proof reports the path overlap, so a caller does not reuse a prior local review or a narrowed validation lane ([test](tests/test_sync_base_preservation.scenario.l1.py))
- Given a branch already current with its base, when the synchronization primitive runs, then the preservation proof reports an empty base delta and an unchanged branch patch identity, so a caller preserves all prior readiness ([test](tests/test_sync_base_preservation.scenario.l1.py))
- Given a caller that already fetched the base before the synchronization primitive runs, when a clean rebase completes, then the proof reports the base advance in `base_delta_paths` — anchored at the branch's fork point rather than the pre-fetch remote ref — so the base delta stays accurate and the caller's lane mapping is not misled by an empty delta ([test](tests/test_sync_base_preservation.scenario.l1.py))
- Given a clean detached HEAD advanced to the base tip, when the synchronization primitive runs, then it emits a readiness-preservation proof reporting the base advance in `base_delta_paths`, no path overlap, and an unchanged branch patch identity — a parked worktree carries no branch work the advance invalidates ([test](tests/test_sync_base_preservation.scenario.l1.py))
- Given a clean detached HEAD already at the base tip, when the synchronization primitive runs, then it emits a preservation proof reporting an empty base delta and an unchanged branch patch identity ([test](tests/test_sync_base_preservation.scenario.l1.py))
- Given a clean rebase whose base advance renames a file, when the synchronization primitive runs, then the proof reports both the old and the new path in `base_delta_paths` — a base rename is not collapsed to the new name, so a base rename of a path the branch also changed surfaces as a path overlap rather than hiding ([test](tests/test_sync_base_preservation.scenario.l1.py))

### Compliance

- ALWAYS: the synchronization primitive resolves the base ref and its remote-tracking form `origin/<base>` through the shared changeset-scope primitives, never re-implementing base, remote-tracking, or branch derivation ([test](tests/test_sync_base.compliance.l1.py))
- NEVER: the synchronization primitive brings a behind-base branch current with `git reset` in any mode — it rebases, preserving the branch's commits, per `spx/21-spec-tree.enabler/14-version-control.enabler/32-sync-base.enabler/13-base-sync-mechanism.adr.md` ([test](tests/test_sync_base.compliance.l1.py))
- NEVER: the synchronization primitive requests an operator decision for a routine behind-base rebase; it returns Git-state outcomes for the skill to act on ([test](tests/test_sync_base.compliance.l1.py))
- NEVER: the synchronization primitive commits or stashes the working tree, aborts a conflicted rebase at operator handoff, or surfaces a dirty tree as a conflict — a dirty tree is a distinct precondition the skill resolves through the commit workflow, per `spx/21-spec-tree.enabler/14-version-control.enabler/32-sync-base.enabler/13-base-sync-mechanism.adr.md` ([test](tests/test_sync_base.compliance.l1.py))
- ALWAYS: `src/plugins/spec-tree/skills/sync-base/SKILL.md` assigns authorized dirty-tree recovery to `/sync-base`: objective work stays on its owning branch, unrelated coordination work follows its own merge route, and `/commit-changes` owns checkpoint policy and proof of success before the primitive is retried within the same invocation ([audit])
- ALWAYS: the recovery contract applies existing authority to the exact changed paths, records checkpoint verification as `passing`, `failing`, or `not-run`, and names the blocked action and evidence separately for absent authority, failed checkpoint, hard Git failure, or unresolved product intent ([audit])
- NEVER: the recovery contract treats an analysis or interview label as a change in authorization or a waiver of an unfinished prerequisite; explicit operator limits govern mutation ([audit])
- NEVER: the skill hands an intermediate authorized `dirty_tree` back as completed synchronization, treats a checkpoint as proof of base currency, or treats `already_current` as proof that the working tree is clean ([audit])
- ALWAYS: the synchronization primitive brings a clean detached HEAD whose commit is an ancestor of the fetched base current by advancing the worktree to `origin/<base>`, never waving it through as a hard failure, per `spx/21-spec-tree.enabler/14-version-control.enabler/32-sync-base.enabler/13-base-sync-mechanism.adr.md` ([test](tests/test_sync_base.compliance.l1.py))
- NEVER: the synchronization primitive advances a detached HEAD behind the base whose working tree has uncommitted tracked changes — it reports `dirty_tree` and leaves the worktree untouched ([test](tests/test_sync_base.compliance.l1.py))
- NEVER: the synchronization primitive advances a diverged detached HEAD — one carrying commits the base lacks — it reports `git_failure` and preserves those commits rather than orphaning them, per `spx/21-spec-tree.enabler/14-version-control.enabler/32-sync-base.enabler/13-base-sync-mechanism.adr.md` ([test](tests/test_sync_base.compliance.l1.py))
- ALWAYS: the readiness-preservation proof carries a schema version and reports the old and new base and branch OIDs as full unabbreviated hashes, and carries no project-specific validation-lane name — lane mapping is the project overlay's, per `spx/21-spec-tree.enabler/14-version-control.enabler/32-sync-base.enabler/13-base-sync-mechanism.adr.md` ([test](tests/test_sync_base_preservation.compliance.l1.py))
- NEVER: a restack brings a stacked branch current with anything but a rebase of the commits above the recorded tip — the branch's own commits survive above the target tip and the stale predecessor commits leave its history, per `spx/21-spec-tree.enabler/14-version-control.enabler/32-sync-base.enabler/13-base-sync-mechanism.adr.md` ([test](tests/test_sync_base_stack.compliance.l1.py))
- NEVER: the synchronization primitive writes a stack record from any input other than git facts at rewrite time or the caller's non-default `--base` — a plain rebase with no dependent and a `--base` naming the default branch write nothing ([test](tests/test_sync_base_stack.compliance.l1.py))
- ALWAYS: a restack onto the default branch removes both stack record keys from the branch's configuration ([test](tests/test_sync_base_stack.compliance.l1.py))
- NEVER: the default branch receives a stack record — a rewritten branch's dependents are the local branches other than the default that contain its pre-rebase head, per `spx/21-spec-tree.enabler/14-version-control.enabler/32-sync-base.enabler/13-base-sync-mechanism.adr.md` ([test](tests/test_sync_base_stack.compliance.l1.py))
- ALWAYS: a branch with no record and no `--base` derives its predecessor by the nearest-fork rule — among several ordered candidates it records the nearest with that fork as the tip, and unordered candidates yield no predecessor and no record, per `spx/21-spec-tree.enabler/14-version-control.enabler/32-sync-base.enabler/13-base-sync-mechanism.adr.md` ([test](tests/test_sync_base_stack.compliance.l1.py))
- NEVER: a failed write or removal of the stack record is reported as a clean synchronization — the result is `git_failure` naming the failed configuration key, per `spx/21-spec-tree.enabler/14-version-control.enabler/32-sync-base.enabler/13-base-sync-mechanism.adr.md` ([test](tests/test_sync_base_stack.compliance.l1.py))
- NEVER: a `--base` synchronization whose default branch does not resolve rewrites a branch that other local branches contain — it reports `git_failure` before movement, leaving HEAD and every stack record unchanged, so the default branch is never mistaken for a dependent, per `spx/21-spec-tree.enabler/14-version-control.enabler/32-sync-base.enabler/13-base-sync-mechanism.adr.md` ([test](tests/test_sync_base_stack.compliance.l1.py))
- ALWAYS: the readiness-preservation proof reports the stack predecessor and the recorded tip before and after the sync as full OIDs or null under its schema version ([test](tests/test_sync_base_stack.compliance.l1.py))
