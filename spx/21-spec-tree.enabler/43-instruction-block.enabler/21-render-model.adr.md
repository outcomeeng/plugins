# Instruction Block Render Model

The product's Spec Tree instructions live as a generated **router block** at the top of each root agent-harness instruction file — `CLAUDE.md` for Claude Code and `AGENTS.md` for Codex — because root instruction files are retained across context compaction while `spx/` subdirectory instruction files disappear from the compacted conversation. Each root file is three content kinds: the generated router block, always first; **`shared` regions** kept byte-identical across both files; and **independent content** free to differ between the files. The router carries the product-neutral WHEN-to-invoke routing and a concrete instruction to read the whole file, so a product's own phase commands survive compaction as content the agent reads rather than as data the router resolves. The writer removes `spx/CLAUDE.md` and `spx/AGENTS.md` so the root surface is the only instruction surface, and preserves every root instruction-file content outside the router block and the shared regions.

The **router block** is delimited by a single opening marker `<!-- SPEC-TREE v{template_version} langs:{enabled-languages} -->` and a closing `<!-- /SPEC-TREE -->`, rendered from the harness templates committed under `dist/claude/` and `dist/codex/`, filtered to the product's enabled languages and to the reading harness — one authored template, two per-harness renders differing only in the spans the template marks for a harness and each file's own filename. Its opening marker carries only the two fields staleness reads: the dotted template version and the recorded enabled-language list. The router is regenerated in full on every update; a re-render overwrites any hand-edit inside it. It carries no product-specific string and references no per-product command by name; because its instruction is to read the entire file, the agent reaches the product's commands wherever the product writes them, so the router needs no slot to point at.

A **`shared` region** is delimited by `<!-- SPEC-TREE:shared {name} -->` and `<!-- /SPEC-TREE:shared {name} -->`, present in both root files under the same name with byte-identical bodies. Shared regions are the dominant content because in almost all repositories the two root files are identical. When a shared region's two bodies diverge, the region is reconciled by **whole-side replacement**: the side whose region was committed more recently — decided by that region's own line-range history, not the whole file's last commit, so a later commit to a file's independent content never carries a stale region — is written whole into the other file. The reconciler never merges the two bodies — a content merge needs semantic judgment a deterministic step cannot supply, so whole-side replacement is the rule that keeps every step reducible to a hook. **Independent content** is every part of a root file outside the router block and every shared region; it is per-file, may differ between the two files, and the writer preserves it verbatim.

The tool is a validator over the last committed git state of the two root files. It **fixes the deterministic cases** — regenerating a stale router block to the installed template, and reconciling a diverged shared region by git-recency whole-side replacement — and **refuses the ambiguous cases**, handing them to the `/update-instruction-block` skill for operator reconciliation. It makes no change to a root file carrying uncommitted working-tree changes, surfacing the divergence instead, because the committed state is the only authoritative input. The router re-render runs as a no-agent pre-commit hook and refresh workflow; the shared-region reconcile is reducible to the same — whole-side replacement keeps it a total function rather than a semantic merge — and runs through the `/update-instruction-block` skill, which applies the git-recency case and escalates only the tie, one-sided, and dirty cases.

The **bootstrap pass** is the single assumption the tool makes on first encounter, before the operator is aware of the `shared` mechanism. It inserts the router block at the top of each root file and wraps at most one shared region: the single biggest contiguous identical span across the two files, and only when that span covers more than 80% of the larger file. When no span reaches that threshold the tool wraps nothing and inserts only the router block. A **delegating root file** — one whose entire independent body does nothing but point the reader at the other root instruction file — carries no content of its own, so the bootstrap treats it as content-absent and adopts the content-bearing side's body before the span is measured, which makes the two bodies identical and the wrap unconditional. Naming the other file is necessary but never sufficient for that verdict: a line that names it while joining a clause of its own states an instruction, so the body keeps its content. The verdict errs toward preserving content, because adoption runs once and replaces the body — an unrecognized pointer costs the file only its shared region, while a misread instruction costs the file the content it declares. A seed already carrying a malformed `shared` fence — an unclosed open marker or a name opened more than once — is never wrapped: the bootstrap inserts only the router and leaves the fence as independent content surfaced as stale drift, rather than burying the dangling marker inside a new region and stranding the surface in a permanently stale state. After this pass the operator sees `shared` in the files and owns the sharing granularity; the biggest-span, one-block, 80% rule never runs again. Six initial situations reach the same target — both root files present as regular files, the router block at the top of each, shared regions byte-identical, independent content per file:

- Only one root file present → the other is created identical → the shared body is one region under the router block.
- One root file a symlink to the other → both become regular files, identical by construction → one shared region under the router block.
- One root file delegating to the other → the delegating body is replaced by the content-bearing side's body → one shared region under the router block, and the pointer does not survive.
- Both present and identical with no managed block → the content is wrapped as one shared region and the router block inserted above it.
- Both present and identical carrying a retired managed block → the retired block is replaced by the router block at the top and the remainder wrapped shared.
- Both present and differing → the biggest contiguous identical span over 80% of the larger file becomes one shared region under the router block and the differing remainder stays independent; at or below the threshold, only the router block is inserted.

Generation reads the built harness templates under `dist/`, not the authored `src/` template, because authored templates can carry build-time macros — runtime-token calls — that are valid source but invalid instruction-block output; the built copies are the authority for what a router block may contain, and an unresolved-macro guard fails generation when `dist/` is stale or malformed. The parse, version-compare, language-filter, harness-filter, render, biggest-identical-span, and shared-region parse-and-set functions are pure over content strings; language detection, git-state and filesystem reads (including the per-region commit-timestamp recency read that decides a diverged region's winner), symlink replacement, obsolete `spx/` instruction-file removal, and the two root file writes live only at the writer's thin CLI edge and the gate that drives it.

## Rationale

One repository is worked by several agents at once, and each harness reads a root instruction filename before any `spx/` subdirectory file. Compaction preserves root instructions and drops subdirectory content, so the router lives in the surface the harness retains.

Instructing the agent to read the whole file is what lets the router stay product-neutral while a product's own commands still reach the agent. The rejected alternative — rendering each product command into a named slot and parsing it back out to reconcile it across the two files — uses the rendered Markdown as its own database, and that parser is the defect-prone surface: a marker quoted in prose, a fence inside a code block, a byte-versus-stripped comparison, a collapsed blank run, and a slot reordered on repair are all failures of reading structured data back out of generated prose. A read-the-whole-file instruction removes the need to point at a command, so the product's commands are ordinary content and no parser exists.

Keeping the two root files identical is the dominant real state, so the tool treats identical content as shared by default and maximizes shared coverage on first encounter; the operator owns how finely to share thereafter, because only the operator knows which spans are intentionally per-harness.

A delegating root file states the same intent by other means: a body that says only "read the other file" declares that the two files carry one set of instructions, so the delegation resolves to identical bodies rather than to a low identical-span ratio. Measuring the span against a pointer instead reads the delegation as divergence — the two bodies share almost nothing — and drops below the threshold, which wraps nothing and leaves each file carrying its own harness's router under a pointer to the other file's differently rendered one. An agent following the pointer then reads the other harness's instructions, the precise misdirection the managed surface exists to prevent. Adopting the content-bearing body is the reading that honors the pointer's intent, and it collapses this situation onto the sole-file case the bootstrap already handles rather than adding a resolution rule of its own. Whole-side replacement for a diverged shared region is what lets a deterministic step reconcile at all — choosing the git-newer side is a total function over committed history while merging two bodies is not — so it is the rule that keeps the reconciliation performable by a deterministic hook rather than by agent judgment. Operating only on committed state, and refusing a dirty working tree, keeps the tool from clobbering an in-progress edit and keeps its input reproducible.

The router reads `dist/` rather than `src/` because authored templates can contain build-time macros, valid source but invalid output; consuming the rendered copies makes the build output the authority. The renderer uses stdlib-parseable fence delimiters rather than a templating engine because the generator ships as a stdlib-only script under `spx/13-plugin-and-runtime-conventions.adr.md`. The accepted cost is that a re-render does not preserve unmodeled hand-prose edits inside the router block; the router is generated boilerplate, and the product's durable truth lives in its specs and decisions and in the root instruction content outside the router block.

Marker recognition anchors to a standalone fence line — a router or `shared` marker quoted inline in a sentence is not a delimiter — but it is not Markdown-fenced-code-block aware: a marker placed alone on its own line inside a `` ``` `` code fence is still read as a real delimiter. The accepted cost is that a product documenting the exact marker syntax keeps the example inline (backticked in a sentence) rather than standalone inside a code fence; the stdlib parser stays a line scanner rather than a Markdown block parser.

## Invariants

- A shared-region reconciliation is a whole-side replacement of one file's region by the other's, never a merge of the two bodies.
- The bootstrap pass wraps at most one shared region, and only when the biggest contiguous identical span exceeds 80% of the larger file; it runs once and never re-derives sharing granularity afterward.
- A root file whose entire independent body only points the reader at the other root instruction file is content-absent to the bootstrap: it adopts the content-bearing side's body before the span is measured, so the pointer never survives as independent content beneath a router.
- A body whose reference to the other root instruction file joins a clause of its own is content-bearing, never delegating; the verdict errs toward preserving content because adoption runs once.
- The router block carries no product-specific string and references no per-product command; a product's commands are content the agent reaches through the router's read-the-whole-file instruction.
- The router re-render runs as a no-agent pre-commit hook and refresh workflow; the shared-region reconcile is reducible to the same and runs through the `/update-instruction-block` skill, which escalates only the cases a deterministic step cannot decide.
