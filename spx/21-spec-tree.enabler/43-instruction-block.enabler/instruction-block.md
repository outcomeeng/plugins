# Instruction Block

PROVIDES deterministic generation and validation of a managed Spec Tree instruction surface in a product's root agent-harness instruction files — `CLAUDE.md` for Claude Code and `AGENTS.md` for Codex — composed of a generated router block rendered from the harness templates committed under `dist/`, `shared` regions kept byte-identical across both files, and independent product content free to differ per file, scoped to the project's enabled languages and rendered per agent harness
SO THAT every agent working a spec-tree project
CAN retain the Spec Tree routing instructions and reach the product's own phase commands across compaction while preserving the product's other root instructions and keeping the two root files consistent

## Assertions

### Scenarios

- Given a template with language blocks and per-harness blocks, when the managed surface is generated for an enabled-language set, then both `CLAUDE.md` and `AGENTS.md` are written, each with its router block first, preserving content outside every managed fence, and containing inside the router block exactly the enabled languages' blocks and only its own harness's blocks ([test](tests/test_instruction_block.scenario.l1.py))
- Given a generation over a file with a `shared` region and independent product prose, when the managed surface is written, then the router block is re-rendered from the template at the top, each `shared` region body is preserved, and independent content outside every fence is preserved verbatim ([test](tests/test_instruction_block.scenario.l1.py))
- Given the router block, when it is written, then its opening marker is `<!-- SPEC-TREE v{template_version} langs:{enabled-languages} -->` carrying only the version and the recorded enabled-language list, its closing marker is `<!-- /SPEC-TREE -->`, and no template-source field is recorded ([test](tests/test_instruction_block.scenario.l1.py))
- Given the `CLAUDE.md` and `AGENTS.md` outputs of one generation, when they are compared, then they share every line except the per-harness spans the template marks and their own filename; the router content, shared regions, and out-of-fence content are otherwise identical ([test](tests/test_instruction_block.scenario.l1.py))
- Given template version B whose section set is a strict superset of version A, when a version-A managed surface is updated from version B, then both re-rendered router blocks contain the additional section, still carry the recorded enabled languages, and preserve every `shared` region body ([test](tests/test_instruction_block.scenario.l1.py))
- Given a `--template` argument that is a symlink or does not resolve to an existing regular file, when the CLI runs, then the path is validated and rejected before any read, so a faulty argument cannot escape into an unintended file ([test](tests/test_instruction_block.scenario.l1.py))
- Given a template whose frontmatter omits `template_version` while its body carries a router marker with a parseable version, when the CLI runs, then it exits nonzero with `error: template has no template_version` before rendering or writing either root instruction file ([test](tests/test_instruction_block.scenario.l1.py))
- Given a router block whose `template_version` is not parseable as dotted integers, when staleness is checked, then it is treated as stale rather than raising, so a re-render normalizes it to the installed version ([test](tests/test_instruction_block.scenario.l1.py))
- Given root `CLAUDE.md` is a symlink to `AGENTS.md`, when the managed surface is updated, then `CLAUDE.md` becomes a regular file copy and both root instruction files preserve the shared root body outside their harness-specific router blocks ([test](tests/test_instruction_block.scenario.l1.py))
- Given a root instruction file contains a markerless full-file Spec Tree instruction surface, when the managed surface is updated, then the generated full-file body is replaced rather than preserved ahead of the router block ([test](tests/test_instruction_block.scenario.l1.py))
- Given one root instruction file whose body names the other root instruction file within the absolute stub bound, when the managed surface is updated with no operator answer, then that body survives intact, the file is reported as a delegation candidate, and the surface reports `stale` until the answer arrives ([test](tests/test_instruction_block.scenario.l1.py))
- Given a reported delegation candidate and an operator answer naming the side both files take, when the managed surface is updated with that answer, then both files carry the named body wrapped as one `shared` region under each harness's router, so neither file retains the pointer and the two files are identical outside their router blocks ([test](tests/test_instruction_block.scenario.l1.py))
- Given both root instruction files name each other within the absolute stub bound, when the managed surface is updated, then both are reported as delegation candidates and each file keeps its own body under its router block, because no answer names a side and neither carries content the other could take ([test](tests/test_instruction_block.scenario.l1.py))
- Given an operator answer naming a side whose own body points at the other root instruction file, when the managed surface is updated with that answer, then the update is refused and both root files stand unchanged, because adopting that side installs a body sending the reader to a file carrying the same pointer ([test](tests/test_instruction_block.scenario.l1.py))
- Given an operator answer whose adoption would replace a body carrying content of its own rather than a pointer, when the managed surface is updated with that answer, then the update is refused and both root files stand unchanged, because adoption replaces a whole body and no report offered that body up ([test](tests/test_instruction_block.scenario.l1.py))
- Given an operator answer arriving once the bootstrap pass has closed — a root instruction file already carrying a `shared` region or a malformed shared fence — when the managed surface is updated with that answer, then the update is refused rather than written, so no run reports success for an answer nothing applied ([test](tests/test_instruction_block.scenario.l1.py))
- Given an operator answer supplied without the write that applies it, when the CLI runs, then it exits nonzero naming the required write and both root files stand unchanged, so the answer is never discarded behind a clean render ([test](tests/test_instruction_block.scenario.l1.py))
- Given a root instruction file carries a managed block delimited by the alternate `BEGIN MANAGED SPEC TREE INSTRUCTIONS` / `END MANAGED SPEC TREE INSTRUCTIONS` markers and their metadata comment lines, when staleness is checked, then it reports `stale`, and when the managed surface is updated, then the alternate-marker block is replaced in place with the compressed `SPEC-TREE` router marker rather than duplicated ([test](tests/test_instruction_block.scenario.l1.py))
- Given product prose that quotes the literal router marker as an inline example before the managed block, when the managed surface is updated, then only the marker on its own fence line opens the block, so the inline example prose is preserved rather than replaced through the real closing fence ([test](tests/test_instruction_block.scenario.l1.py))
- Given a router block whose body or following independent content quotes the literal `<!-- /SPEC-TREE -->` closing marker inline, when the managed surface is updated, then only the standalone-line closing fence bounds the router block, so the inline-quoted marker and the content around it are preserved rather than swallowed at the quote ([test](tests/test_instruction_block.scenario.l1.py))
- Given product prose that quotes a literal `shared`-region fence as an inline example, when the managed surface is read or written, then only a fence on its own line delimits a `shared` region, so the quoted example is not mistaken for a region opener and the prose is preserved ([test](tests/test_instruction_block.scenario.l1.py))
- Given a root instruction file whose independent product content carries a run of blank lines, when the managed surface is written, then the blank-line run is preserved verbatim rather than collapsed ([test](tests/test_instruction_block.scenario.l1.py))
- Given two root files whose same-named `shared` region diverges and whose region-touching commits carry different dates, when the shared regions are reconciled, then the side whose region was committed more recently is written whole into the other file, decided by that region's own line-range history rather than the whole file's last commit ([test](tests/test_instruction_block.scenario.l1.py))
- Given two root files whose same-named `shared` region diverges, when the shared regions are reconciled, then the losing file's region body is replaced in full by the winning side and no line of the two bodies is blended ([test](tests/test_instruction_block.scenario.l1.py))
- Given two root files whose same-named `shared` region diverges but whose region-touching commits carry the same date, when reconciliation runs, then the tie is reported as an ambiguous case for `/update-instruction-block` reconciliation rather than resolved by guess ([test](tests/test_instruction_block.scenario.l1.py))
- Given a `shared`-region fence present in one root file with no same-named region in the other, when the managed surface is checked, then the mismatch is reported as an ambiguous case for skill reconciliation rather than auto-resolved ([test](tests/test_instruction_block.scenario.l1.py))
- Given a root instruction file carries a malformed `shared` fence — an open marker with no matching closing fence, or a name opened more than once — when the managed surface is checked, then the malformed region is reported as stale drift for skill reconciliation rather than silently skipped or collapsed ([test](tests/test_instruction_block.scenario.l1.py))
- Given two root files carry a malformed `shared` fence and no valid shared region, when the managed surface is written, then the bootstrap does not wrap the malformed fence into a new region — it inserts only the router and leaves the fence as independent content the drift gate reports as stale ([test](tests/test_instruction_block.scenario.l1.py))
- Given a root instruction file with uncommitted working-tree changes, when shared-region reconciliation runs, then it makes no change and reports the dirty file, operating only on committed state ([test](tests/test_instruction_block.scenario.l1.py))
- Given a root instruction file whose router block is preceded by product content, when staleness is checked, then it reports `stale`, so a re-render moves the router back to the first content of the file ([test](tests/test_instruction_block.scenario.l1.py))
- Given two root files whose biggest identical span begins at a line boundary in one file but mid-line in the other, when the bootstrap wraps a `shared` region, then the region is snapped to whole lines in both files, so a harness-specific prefix on the shared line is never split ([test](tests/test_instruction_block.scenario.l1.py))

### Mappings

- For every agent harness and enabled-language subset, rendering the canonical instruction-block template maps to a router block with exactly one blank line between its opening marker and first body content ([test](tests/test_router_spacing.mapping.l1.py))
- Each supported CLI flag maps to a duplicate-flag rejection when it appears more than once in raw arguments, before argument parsing reads a template or repository path ([test](tests/test_instruction_block.mapping.l1.py))
- Over the languages the template defines blocks for, a language's block appears in a rendered router block when the language is in the detected enabled set and is omitted otherwise ([test](tests/test_instruction_block.mapping.l1.py))
- A test-file extension present under `spx/**/tests/` maps to the language it denotes, and the detected enabled-language set is the set of those mappings ([test](tests/test_instruction_block.mapping.l1.py))
- The `--check` verb maps a router-block state to its report: a missing block to `absent`, a version-behind block to `stale`, a version-current block to `current`, and a detected-language set differing from the recorded set to `stale` ([test](tests/test_instruction_block.mapping.l1.py))
- The `--check` verb maps a `shared`-region state to its report: two same-named regions with byte-identical bodies to `current`, two diverged bodies to `stale`, and a region present in only one file to `stale` ([test](tests/test_instruction_block.mapping.l1.py))
- An initial root-instruction-file topology maps to its bootstrap outcome: only one file present maps to the other created identical with one `shared` region under the router; a symlinked file maps to both regular files with one `shared` region under the router; one file whose body names the other within the absolute stub bound maps to both bodies preserved under their routers with no `shared` region, the adoption awaiting an operator answer; both identical with no managed block maps to one `shared` region under an inserted router; both identical carrying an alternate managed block maps to the router replacing that block with the remainder wrapped `shared`; both differing with a biggest contiguous identical span over 80% of the larger file maps to the router plus that one `shared` region and an independent remainder; both differing at or below the threshold maps to the router only ([test](tests/test_instruction_block.mapping.l1.py))
- The enabled-language set maps a section that introduces per-language content but carries no per-language block of its own to its presence in the rendered router: a non-empty set renders that section, and the empty set omits it whole rather than leaving its heading and preamble standing above the tables the same render dropped ([test](tests/test_instruction_block.mapping.l1.py))
- A root-instruction-file body maps to a delegation candidacy from two facts about the file and no reading of its prose: a body naming the other root instruction file whose text is within the absolute stub bound, and one whose text is exactly that bound, each map to a candidate; a body naming it whose text is one character past the bound, and a body naming no other root instruction file, each map to no candidate ([test](tests/test_instruction_block.mapping.l1.py))

### Properties

- For every explicit language token outside the language set declared by the canonical instruction-block template, the CLI rejects the `--languages` override and names every allowed language ([test](tests/test_language_override.property.l1.py))
- Every generated router block's `template_version` equals the installed template version ([test](tests/test_instruction_block.property.l1.py))
- Every rendered managed surface ends with exactly one trailing newline ([test](tests/test_instruction_block.property.l1.py))
- Staleness ordering matches dotted-numeric version order: a product version is stale exactly when it is numerically below the installed template version ([test](tests/test_instruction_block.property.l1.py))
- Every reconciled `shared` region body is byte-identical in `CLAUDE.md` and `AGENTS.md` ([test](tests/test_instruction_block.property.l1.py))
- The bootstrap pass wraps at most one `shared` region for any pair of root-file contents ([test](tests/test_instruction_block.property.l1.py))
- For every pair of root-file contents, the biggest contiguous identical whole-line span determines the wrap decision from its length over the larger file: one `shared` region above the threshold and no region at or below it ([test](tests/test_instruction_block.property.l1.py))
- Reconciling an already-byte-identical `shared` region is idempotent — the two files are unchanged ([test](tests/test_instruction_block.property.l1.py))

### Compliance

- ALWAYS: generation emits and validates a strongly warned authority hierarchy of operator → active skills → repository decisions and specs → verification evidence → code, states that centrally managed skills outrank stale repository content, and requires a lower layer to be fixed rather than weakening a higher layer ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: generation emits and validates that an active skill loads a matching `spx/local/*.md` overlay only when the skill declares one, and that the overlay supplies repository-specific values and commands below the skill without replacing, weakening, or contradicting it ([test](tests/test_instruction_block.compliance.l1.py))
- NEVER: generation permits code comments or docstrings to reference Spec Tree specs or decisions through `spx/...` paths, ADR/PDR identifiers, or decision-file references ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: generation emits and validates that the active harness guide in every directory is read before work in that directory when the guide exists — `CLAUDE.md` for Claude Code and `AGENTS.md` for Codex ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: generation emits and validates a dangerous-command guard rule that forbids dynamic branch names in `git branch -d` and `git branch -D`, including variables, command substitutions, arrays, and globs even when quoted or placed after `--`; requires every branch name to be literal; and permits several literal names in one invocation ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: agents obey an emitted dangerous-command guard by abandoning the blocked command family without reformulation or equivalent-command substitution, using only sanctioned alternatives, or reporting the redacted command, purpose, and guard reason before stopping for operator direction ([audit])
- ALWAYS: generation emits a stop trigger that invokes `/wait-for-load` before every test, eval, build, or validation command, waits for `ready: true`, then runs the selected command unchanged, and never uses host load to reduce scope, workers, limits, deadlines, or verification; the Codex router additionally requires the waiter and selected command to run in separate top-level `functions.exec` calls, makes the nested waiter yield before its outer call, accepts readiness only from visibly returned terminal JSON, collects yielded nested processes by exact `session_id` through later top-level `write_stdin` calls whose outer yield window exceeds the nested collection yield, and reconciles every owned process handle to terminal exit or explicit interruption before another process sequence, operator question, merge or publication, or turn end rather than leaving a background terminal dangling ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: generation emits and validates a managed router that requires a live `SPEC_TREE_FOUNDATION` marker before direct filesystem access under `spx/` or access to source and test content, while exempting `spx session` operations — including inspection, archive, and release — `spx worktree status`, `spx diagnose`, and no-patch Git status, history, and topology until their output is followed into product content ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: both harness routers carry one harness-neutral sub-agent dispatch authorization declaring the router's own named verifier and reviewer roles pre-authorized, forbidding an operator confirmation before dispatching one, forbidding dispatch of a role the router does not name, forbidding a verification skill run in the main conversation, and blocking the gate when a named role cannot be dispatched or does not return; each harness block carries only its own dispatch mechanics ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: for every configured verifier and reviewer role the routers name, the role-task contract states the output contract the shipped thin agent definition for that role produces — a structured verdict or a sealed-run journal token — together with how a caller reads that contract's result and what blocks the gate; a contract naming a shape its role's definition does not produce is drift the render carries into every consumer ([audit])
- ALWAYS: the Codex router block begins with the operator-override rule as its first rendered body content, before the `Spec Tree Instructions` heading, while the Claude router block omits that Codex-only rule ([audit])
- ALWAYS: when the operator asks a question, both harness routers revoke mutation privileges, stop destructive or state-changing non-verification processes, preserve running verification unless the operator explicitly instructs that process to stop, and require an immediate answer ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: the Codex router block acquires subagents through individual sequential `multi_agent_v1.spawn_agent` calls, records each returned agent id verbatim before issuing another spawn, permits already-spawned agents to execute concurrently, and forbids fail-fast batched spawning, fabricated agent ids, and hard-coded thread limits ([audit])
- ALWAYS: the Codex router block governs every spawned subagent through a registry-driven lifecycle that preserves the complete final result before immediate close, treats timeout as non-final, closes abandoned work explicitly, reconciles known ids before new spawning and after spawn failure, interruption, or compaction, and leaves no known subagent open before asking the operator, merging, publishing, or ending the turn ([audit])
- ALWAYS: the Codex router requires deferred-tool discovery before reporting a named agent or lifecycle capability unavailable, treats an exact role match in the typed `spawn_agent` schema's `Available roles` list as runtime authority, rejects initial catalogs, tool lists, generated rosters, and local agent files as availability evidence, and discovers `spawn_agent`, `wait_agent`, and `close_agent` through the complete deferred registry when they are not initially exposed ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: generation writes the managed surface in both root `CLAUDE.md` and root `AGENTS.md`, never one without the other — each agent reading the same repository gets its own harness router block in the root instruction file it retains across compaction ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: generation places the router block first in each root file ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: generation emits a concrete instruction directing the reader to read the entire root instruction file ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: the Codex router applies verifier spawning only to the main authoring conversation; an already-dispatched verifier executes its configured methodology directly and never searches for or launches another verifier through typed-agent discovery or an external agent CLI ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: instruction-block generation reads the harness-specific templates from `dist/claude/` and `dist/codex/`, so the update surface consumes the same rendered output this product ships as installed plugin trees ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: instruction-block writing is exposed to agents through the repository Justfile recipe `just build-instructions`; `just instructions-check` is the drift gate over the same writer ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: the pre-commit hook regenerates the root managed surface through `just build-instructions` — the rendered-`dist/` template writer — never by invoking the generator directly against the authored `src/` template ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: the drift gate reports missing root instruction-file paths as drift and marks only existing generated instruction-file paths with `--intent-to-add`, so deleted `spx/CLAUDE.md` and `spx/AGENTS.md` instruction files are reported by `git diff` without causing a missing-path failure ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: regenerating a drifted router block overwrites the drift — a re-render restores the template's content over any hand-edit, the basis of the regenerate-and-diff gate that keeps both files current without an agent invocation ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: the refresh workflow regenerates skill output and the root managed surface, then opens or updates a pull request only when git drift exists ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: the refresh workflow checks out the default branch `main`, so its regeneration and drift comparison run against the published tree ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: the refresh workflow verifies the pinned `just` download against its recorded SHA-256 checksum before installing it, so a tampered or moved release fails the run rather than executing ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: the refresh workflow provisions `dprint` before regenerating skill output, because `just build-skills` formats generated `dist/` output with `dprint` and fails without it ([test](tests/test_instruction_block.compliance.l1.py))
- ALWAYS: rendering preserves brace-delimited template tokens byte-for-byte ([test](tests/test_instruction_block.compliance.l1.py))
- NEVER: the router block carries product-specific prose — per-product commands live only as content the read-the-whole-file instruction reaches ([audit])
- NEVER: the generator recognizes a `SPEC-TREE:{name}` slot fence as a managed command slot — the fence is ordinary independent content, never a slot the router resolves by name ([test](tests/test_instruction_block.compliance.l1.py))
- NEVER: a `shared`-region reconciliation blends the two bodies — the losing file's region is replaced whole by the winning side ([test](tests/test_instruction_block.compliance.l1.py))
- NEVER: an update keeps an unmodeled hand-prose edit inside the router block — a re-render reflects only the template, the recorded enabled languages, and the harness, while `shared` regions and independent content are preserved ([test](tests/test_instruction_block.compliance.l1.py))
- NEVER: generation emits a router block containing the session-result archive instruction token or the `result` session frontmatter field token ([test](tests/test_instruction_block.compliance.l1.py))
- NEVER: instruction-block generation writes output from a harness template that still contains unresolved build-template delimiters such as `{{! ... !}}` ([test](tests/test_instruction_block.compliance.l1.py))
- NEVER: `spx/CLAUDE.md` or `spx/AGENTS.md` remain after generation — the root managed surface is the canonical instruction surface ([test](tests/test_instruction_block.compliance.l1.py))
