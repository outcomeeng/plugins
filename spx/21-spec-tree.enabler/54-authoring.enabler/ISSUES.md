# Issues: Authoring

Coordination note; not spec truth. Reconcile against `authoring.md`, its two children, and current intent before acting.

## `/spec` is declared and not built; `/author` is still the operator-facing entry

`authoring.md` declares `/spec` as the operator-facing specification workflow that owns requirements convergence and delegates decision-ready writes to `/author`, with `/author` an internal protocol invoked with a decision-ready artifact packet. Neither holds today: no `/spec` skill ships, and `/author` remains public and operator-facing. The two children exist and are ordered — `spx/21-spec-tree.enabler/54-authoring.enabler/39-artifact-authoring.enabler` (decision-ready artifact mutation and validation protocol) provides to `spx/21-spec-tree.enabler/54-authoring.enabler/69-spec-workflow.enabler` (`/spec` persistence and validation steps).

**Sequence model.** Every declaration-changing sequence starts with `/spec` unless another orchestrator already holds a decision-ready artifact packet. `/author` writes artifacts only after scope, structure, placement, and content are settled.

| Starting state                                       | Valid sequence                                                                                                                  |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Empty tree                                           | `/spec` → `/bootstrap` → `/decompose spx/` → `/author`                                                                          |
| Existing artifact, settled change                    | `/spec` → `/contextualize` → `/author` → `/align`                                                                               |
| Existing artifact, unsettled requirements            | `/spec` → `/contextualize` → `/interview` → `/author` → `/align`                                                                |
| New artifact with unambiguous ownership              | `/spec` → `/contextualize` → `/interview` when needed → `/author` → `/align`                                                    |
| New nodes or unsettled decision ownership            | `/spec` → `/contextualize` → `/interview` when needed → `/decompose` → `/author` → `/align`                                     |
| Structure-preserving move or re-scope                | `/spec` → `/contextualize` → `/interview` when needed → `/refactor` → `/author` → `/align`                                      |
| Plan names nodes that do not exist                   | `/slice` → `/spec` → `/decompose` or `/author` → `/slice` → `/apply`                                                            |
| Apply finds an entailed declaration gap              | `/apply` → `/contextualize` → declaration-readiness check → `/author` → applicable declaration audit → resume the per-node flow |
| Apply finds an unsettled product or structure choice | `/apply` → `/spec` → `/slice` when the queue changes → resume `/apply`                                                          |

**First slice.** A product operator invokes `/spec <full-artifact-path-or-settled-intent>` with an existing artifact path or one new artifact whose type, parent, and index are uniquely determined by loaded context. The workflow gathers only unresolved content decisions, writes the artifact through `/author`, aligns affected lower declarations, validates the result, and reports the next executable handoff. Before mutation, its first useful failure reports the unresolved ownership or structure decision and the exact `/decompose` or `/refactor` handoff. Inspection surfaces: the `/spec` result report, changed declaration paths, `spx spec context`, `spx spec status --format json`, and the merged changeset. Verification: spec audits, routing evals, `skill-auditor`, `spx validation markdown`, `spx spec status --format json`, `just check-skills`, `just docs-check`, whole-changeset review, and the repository full gate after agentic gates converge. The slice applies, in ascending index order, `spx/21-spec-tree.enabler/35-evidence.enabler`, the two children above, `spx/21-spec-tree.enabler/65-apply.enabler`, and `spx/21-spec-tree.enabler/68-audit.enabler/32-audit-specs.enabler`.

Two merge cycles carry it. The first stabilizes the declaration form: a node heading describes claim shape independently of the verification type `/test` selects, `/audit-specs` accepts the canonical universal audit rule under `### Compliance` consistently, and eval cases reproduce the two prior contradictory verdicts (identical canonical `### Compliance` audit assertions received both APPROVED and REJECTED spec-auditor verdicts, while `### Audit` received deterministic REJECTED verdicts). The second adds artifact-class routing to `/apply` before language detection so skill-backed nodes invoke `/create-skill`, skill validation, and `skill-auditor`, with language architecture, test, and code skills running only when the implementation artifact requires that language; then makes `/author` internal and packet-driven, adds public `/spec`, and covers existing-artifact updates plus one unambiguous new artifact. The second cycle starts only after the canonical shape yields one stable APPROVED result. The broader verification-heading migration is tracked in `spx/21-spec-tree.enabler/35-evidence.enabler/ISSUES.md` because it requires per-file judgment across roughly 75 node specs.

**Later slices.** Structural routes: `/decompose` returns a settled structure packet and delegates every child-spec write to `/author`; `/refactor` delegates declaration rewrites to `/author` after applying the settled structural operation; `/slice` plans with missing nodes route through `/spec`; `/bootstrap` stays the empty-tree specialist behind the `/spec` entry point. Apply readiness: a declaration-readiness preflight in `spx/21-spec-tree.enabler/65-apply.enabler` before architecture begins; `/apply` invokes `/author` only when loaded declarations uniquely determine the artifact change; every unresolved product, scope, ownership, or structure decision routes through `/spec`; language architect skills return decision-ready ADR content persisted through `/author`; slice selection re-runs when declaration work changes the node queue. Surface migration: replace public `/author` guidance in the root router, README, contextualization failures, bootstrap routing, and skill cross-references with `/spec`; mark `/author` `user-invocable: false` with a passive packet-contract description; add eval evidence for `/spec` routing and audit evidence that `/author`, `/decompose`, `/refactor`, and language architect skills no longer duplicate declaration orchestration; rebuild both generated plugin trees and verify both catalogs expose `/spec` while hiding `/author` from operator autocomplete.

**Constraints.** `/spec` owns operator interaction; `/author` owns deterministic artifact mutation. `/apply` may author only a change uniquely entailed by loaded declarations. `/decompose` remains the sole owner of node boundaries, ordering evidence, and indices. `/test` remains the sole owner of verification-type and assertion-type selection. A declaration change reaches its delivery boundary through the repository merge lifecycle after declaration audits and deterministic validation pass.
