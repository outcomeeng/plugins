# ISSUES — audit-eval-evidence

## Producer-coupling verdict model superseded by adapter-derived-evals

`spx/31-outcomeeng.enabler/31-verification.enabler/31-eval-verification.enabler/15-adapter-derived-evals.adr.md` decides, methodology-wide for skill, agent, and command behavior, that eval evidence reaches the installed plugin through the adapter contract and that a model-facing prompt derived from a producer artifact's text is not evidence for that producer's shipped behavior.

This node's methodology contradicts that decision. `audit-eval-evidence.md` and its shipped skill's `references/evidence-model.md` classify `prompt_source.kind = "producer-section"` prompt materialization as Prompt-loaded coupling with a **Proceed** verdict for claims about skill, agent, or classifier behavior — the exact evidence path the decision supersedes. Per the truth hierarchy the decision governs and this auditor is the lower surface not yet caught up; the decision names it as such and stays authoritative in the interim.

**Resolution shape.** Re-derive the producer-coupling model here to the adapter-invoked coupling category the decision declares: an eval reaching the installed plugin through the adapter contract is the coupled case, producer-section (and producer-file, producer-files) prompt materialization stops earning a Proceed verdict for skill/agent/command-behavior claims, and the five-property evidence model gains the adapter-invoked category. This edits the shipped `src/plugins/spec-tree/skills/audit-eval-evidence/` surface (`SKILL.md`, `references/evidence-model.md`) and this node's spec, so it carries a plugin version bump, `dist/` regeneration, and the typed skill-auditor gate.

**Why deferred, not fixed in the introducing changeset.** The full re-derivation is the eval-verification cutover, already scoped as future work in `spx/31-outcomeeng.enabler/31-verification.enabler/31-eval-verification.enabler/PLAN.md` and `spx/13-infrastructure.enabler/25-eval-harness.enabler/PLAN.md`: the shipped `outcomeeng_evals` harness and its governing specs re-home into the eval-verification subtree with execution machinery consumed from the external component per `spx/31-outcomeeng.enabler/31-verification.enabler/18-verification-component.adr.md`. Flipping producer-section from Proceed to reject here ahead of that cutover, without the adapter-invoked replacement category, would make this auditor reject the only coupling mode the shipped harness currently produces — a regression. The auditor aligns with the harness at the cutover, not before it.

**Evidence.** Surfaced by the CI changeset reviewer on the adapter-derived-evals decision changeset (PR #482) as a `[consistency]` finding: the new methodology decision and this shipped auditor give contradictory verdicts for a `producer-section` skill eval, with the decision the higher layer.
