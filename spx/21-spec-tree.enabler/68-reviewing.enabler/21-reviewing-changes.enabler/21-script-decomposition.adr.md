# Script Decomposition for Reviewing Changes

The review-changes skill decomposes into one policy module plus four single-purpose CLI scripts under `plugins/spec-tree/skills/review-changes/scripts/`. The policy module `review_result.py` declares the canonical schema — `SCHEMA_VERSION`, the `Severity`/`Concern` enums, the frozen `Finding` and `ReviewResult` dataclasses, the `ReviewResultValidationError` exception, and the `parse_json` / `to_json_dict` / `from_json_dict` entry points; a review carries findings only, with no `decision`/verdict field, so each consumer applies its own policy. `validate_review_result.py` is the arbiter: it calls `review_result.parse_json` and exits non-zero on any violation. `compute_diff.py` resolves the current thread, the optional `changes.json` override, and `base_ref`/`head_ref` through their precedence chains — a git-derived `base_ref` composed to the remote-tracking form `origin/<base>` via `changeset_scope.remote_tracking_ref` per `spx/21-spec-tree.enabler/14-version-control.enabler/15-changeset-scope.enabler/13-changeset-derivation.adr.md` so a stale local branch ref cannot widen the diff — then emits labeled sections for `git diff <base_ref>...<head_ref>` (committed three-dot merge-base), `git diff --cached` (staged), `git diff` (unstaged), and `git ls-files --others --exclude-standard` plus `git diff --no-index` (untracked files). `render_review.py` parses the result, loads the per-section templates from `references/render/`, partitions findings by render class, and emits `review.md`. Every filesystem effect routes through the `thread_store` facade; the swappable review prompt lives at `references/review-prompt.md` loaded via `${CLAUDE_SKILL_DIR}`; the scripts chain via stdin/stdout pipes; and the wrapper agent reaches the scripts only by invoking the skill, validating every JSON document it emits through the arbiter before persistence.

## Rationale

A separate policy module from the CLI scripts because the canonical schema — enum membership, required keys, the path-style `rule` citation form — is what the skill validates; `parse_json` enforces it before returning, making validation total over every entry path, while the arbiter CLI surfaces the result as an exit code the wrapper agent reads. Dataclasses plus enums over a JSON Schema document because the marketplace's `verdict.py` sets that stdlib precedent and a second representation invites drift. Frozen dataclasses because instances cross the parse-then-validate boundary as values. `compute_diff` auto-derives `base_ref` through a precedence chain rather than taking a flag because a flag is extra state three surfaces would drift on, composes the git-derived base to its remote-tracking form so the committed diff is taken against the fetched `origin/<base>` rather than a bare local ref that can lag in a multi-worktree checkout, and appends staged, unstaged, plus untracked diffs so local review covers the full working changeset. `render_review` parses before rendering so a `review.md` is never produced from an unvalidated result. The render templates are data, not code, because the GH-hosted review workflow consumes the same shape and embedding it in Python f-strings guarantees drift. Piping over intermediate files because each intermediate file is another place two scripts can disagree on a path.

## Verification

### Testing

- ALWAYS: the policy module `review_result.py` declares `SCHEMA_VERSION`, frozen `Finding` and `ReviewResult` dataclasses, the `Severity`/`Concern` enums, the `ReviewResultValidationError` exception, and the `parse_json` / `to_json_dict` / `from_json_dict` entry points ([compliance])
- ALWAYS: the review-result schema carries no `decision`/verdict field — a review produces findings only, and each consumer applies its own policy by validity and phase ([compliance])
- ALWAYS: `validate_review_result.py` invokes `review_result.parse_json` for validation — the arbiter does not re-implement schema knowledge ([compliance])
- ALWAYS: `compute_diff.py` resolves the thread via `thread_store.current_slug()`, reads the optional `changes.json` override through the facade, resolves `base_ref` and `head_ref` through their precedence chains — a git-derived `base_ref` is composed to the remote-tracking form `origin/<base>` via `changeset_scope.remote_tracking_ref` so a stale local branch ref cannot widen the diff — and emits labeled sections for committed merge-base, staged, unstaged, and untracked diffs — no `base_ref` source means a non-zero exit naming all three sources ([compliance])
- ALWAYS: `render_review.py` parses `review-result.json` through `review_result.parse_json` before emitting markdown, loads the per-section templates, partitions findings by render class, and exits non-zero on an invalid result before producing any surface ([compliance])
- ALWAYS: the swappable review prompt at `references/review-prompt.md` is loaded by skill prose via `${CLAUDE_SKILL_DIR}/references/review-prompt.md` — the prompt is data the skill loads, never code ([compliance])
- ALWAYS: the per-section render templates under `references/render/` are loaded by `render_review.py`, and every render-shape literal lives in a template file, never as a Python constant ([compliance])
- ALWAYS: the wrapper agent at `plugins/spec-tree/agents/changes-reviewer.md` reaches the scripts only by invoking the skill — its prose contains no `${CLAUDE_SKILL_DIR}`, no `${CLAUDE_PLUGIN_ROOT}`, and no hard-coded path into `scripts/` ([compliance])
- ALWAYS: frozen dataclasses are used for `Finding` and `ReviewResult` — instances are values that cannot be mutated between parse and validate ([compliance])
- NEVER: a CLI script under `scripts/` calls `open()`, `pathlib.Path.write_*`, `os.remove`, or any direct filesystem primitive against the thread-store backend's storage paths — every read and write routes through `thread_store` ([compliance])
- NEVER: a second representation of the schema is authored — `review_result.py` is the canonical schema ([compliance])
- NEVER: the review prompt is embedded inside `SKILL.md` or any `*.py` file — it is one standalone markdown file at the declared reference path ([compliance])
- NEVER: render template content is embedded inside `render_review.py` or any script as f-string literals — the templates are standalone markdown files under `references/render/` ([compliance])
- NEVER: a script under `scripts/` imports a third-party package, depends on `uv` at runtime, or imports any `outcomeeng_*` module — stdlib only ([compliance])

### Audit

- NEVER: the reviewer emits a `decision`/verdict, or a surface posts an `APPROVE`/`REQUEST_CHANGES` review on the reviewer's behalf — a review produces findings only; the consumer applies its own policy by validity and phase, never by severity ([audit])
- NEVER: the wrapper agent hand-validates JSON it just emitted by re-checking enum membership or required keys in agent prose — the arbiter CLI is the single source of validity ([audit])
- NEVER: an intermediate file is used between two scripts in the chain when stdin/stdout suffices — pipes over files when fanout does not demand a directory ([audit])
