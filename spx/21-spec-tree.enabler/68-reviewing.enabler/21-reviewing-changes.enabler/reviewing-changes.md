# Reviewing Changes

PROVIDES a verification skill that produces a structured judgment-style review of working changes against an explicit base ref, parses the review-result JSON through a Python policy module as the validity gate, records the run on `spx journal --type review`, and renders the human-readable surface from the sealed event prefix
SO THAT developers reviewing their own changes before opening a PR and CI reviewing a branch's diff against its base ref
CAN obtain a deterministically-validated review (structured findings only) — the reviewer emits findings, and each consumer applies its own policy (by validity and phase per `spx/15-merging.pdr.md`, never by severity)

## Assertions

### Scenarios

- Given `SPX_VERIFY_BASE_REF` set in the environment, the script chain uses the env value as `base_ref`, computes the diff, and streams the run live on `spx journal --type review` — `journal_emit.py scope-entered`, a `journal_emit.py scope-advanced` per examined changed file, a `journal_emit.py finding-reported` per finding (the per-finding parse is the validity gate), and `journal_emit.py run-completed` — then renders the human-readable surface from the sealed event prefix ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given no `SPX_VERIFY_BASE_REF` AND `git symbolic-ref refs/remotes/origin/HEAD` resolves, the script chain uses that symbolic ref reduced to its remote-tracking form `origin/<base>` (stripping the `refs/remotes/` prefix) as `base_ref` — a remote-tracking ref per `spx/21-spec-tree.enabler/14-version-control.enabler/15-changeset-scope.enabler/13-changeset-derivation.adr.md`, so a stale local branch ref cannot widen the diff ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given no `SPX_VERIFY_BASE_REF` AND no `refs/remotes/origin/HEAD` symbolic ref, `compute_diff.py` exits non-zero with a stderr message naming both sources so the operator can identify which to populate ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given `SPX_VERIFY_HEAD_REF` set in the environment, `compute_diff.py` uses that value as `head_ref` instead of the default `HEAD` ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given no `SPX_VERIFY_HEAD_REF`, `compute_diff.py` uses the literal `HEAD` as `head_ref` — `head_ref` has a default; `base_ref` does not ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given committed feature changes, staged changes, unstaged changes, and untracked files in the working tree, `compute_diff.py` includes all four as labeled sections in the review input so local review sees every change the next push or commit can carry ([test](tests/test_skill_orchestration.scenario.l2.py))
- Given `compute_diff.py --bundle-dir <dir>`, the script writes a caller-owned scratch review-input bundle outside the git worktree containing `diff.md` and `manifest.json`, and stdout reports the two paths plus the diff byte count and section count so the reviewer can read the diff with random access while durable review state remains journal-only ([test](tests/test_skill_orchestration.scenario.l2.py))
- `review_result.parse_json` returns a `ReviewResult` dataclass on a conforming document and raises `ReviewResultValidationError` on every violation — a missing required key, an unknown `severity` or `concern` value, or a malformed citation — naming the offending value ([test](tests/test_review_result.scenario.l1.py))
- `review_result.to_json_dict` and `review_result.from_json_dict` round-trip a `ReviewResult` instance without loss ([test](tests/test_review_result.scenario.l1.py))

### Mappings

- `Severity` enum members map to the wire values `blocking`, `debt` ([test](tests/test_review_result.scenario.l1.py))
- `Concern` enum members map to exactly the six wire values `consistency`, `security`, `performance`, `evidence`, `standards`, `architecture` ([test](tests/test_review_result.scenario.l1.py))
- Review-result severities map into the shared run-journal projection as `blocking` → `reject` and `debt` → `warning`; the projection then owns the terminal status rollup from the sealed prefix ([test](tests/test_review_journal_emit.mapping.l1.py))
- `journal_emit.py render` maps the sealed prefix's finding severities back to the per-class counts `blocking` → BLOCKING and `debt` → DEBT for the `BLOCKING: <n>, DEBT: <n>` count line — the mapping is total over `Severity` ([test](tests/test_review_journal_emit.mapping.l1.py))
- `journal_emit.py finding-reported` parses one finding through `review_result.parse_finding_json` (the per-finding validity gate) and prints its `verification.finding.reported` event; a malformed finding exits non-zero naming the violation with no event emitted, before any journal append ([test](tests/test_review_journal_emit.mapping.l1.py))

### Properties

- For every `ReviewResult` instance, `from_json_dict(to_json_dict(r)) == r` — serialization is lossless ([test](tests/test_review_result.property.l1.py))

### Compliance

- ALWAYS: the `review_result.py` policy module declares `SCHEMA_VERSION`, frozen `Finding` and `ReviewResult` dataclasses, and the `Severity` and `Concern` enums — the canonical review-result schema lives in one Python module ([test](tests/test_review_result.scenario.l1.py))
- NEVER: the review-result schema carries a `summary`, acknowledgement, `decision`, or verdict field — a review produces findings only; each consumer (the `REVIEW_READINESS` local gate, the `MERGE_READINESS` CI review, the author) applies its own policy by validity and phase per `spx/15-merging.pdr.md` — never by severity — and the reviewer never decides ([test](tests/test_review_result.scenario.l1.py))
- ALWAYS: the review prompt instructs the reviewer to review the whole diff against the whole shared taxonomy using the repository's own instructions, and to treat any caller-supplied scope, severity pre-filter, or emphasis as non-authoritative — the local reviewer runs at parity with the CI reviewer per `spx/15-merging.pdr.md` ([audit])
- ALWAYS: the `review-changes` skill prose loads repository-root `REVIEW.md` when present before the swappable review prompt, applies it as the repository-local review override, and reads no review template or example files ([audit])
- ALWAYS: scripts under `plugins/spec-tree/skills/review-changes/scripts/` write no durable review state directly; `compute_diff.py` may write only the caller-owned scratch review-input bundle files (`diff.md`, `manifest.json`), and every other script uses no direct storage-write primitive ([test](tests/test_reviewing_changes.compliance.l1.py))
- ALWAYS: the swappable review prompt template lives at `plugins/spec-tree/skills/review-changes/references/review-prompt.md` and the skill prose loads it via `${CLAUDE_SKILL_DIR}/references/review-prompt.md` ([audit])
- ALWAYS: `compute_diff.py` includes four labeled review input sections when content exists: `git diff <base_ref>...<head_ref>` for committed three-dot merge-base semantics, `git diff --cached` for staged changes, `git diff` for unstaged changes, and `git ls-files --others --exclude-standard` plus `git diff --no-index` for untracked files. `head_ref` defaults to `HEAD` if not configured via `SPX_VERIFY_HEAD_REF` env, and a git-derived `base_ref` is the remote-tracking form `origin/<base>` per `spx/21-spec-tree.enabler/14-version-control.enabler/15-changeset-scope.enabler/13-changeset-derivation.adr.md`. The committed section shows what the head added since branching from the base, independent of how far the base has moved and independent of a stale local branch ref, while the staged, unstaged, and untracked sections keep local review aligned with the full working changeset. When invoked with `--bundle-dir`, the same review input is written to caller-owned scratch files (`diff.md`, `manifest.json`) outside the git worktree for random access; the bundle is not durable review state ([test](tests/test_skill_orchestration.scenario.l2.py))
- ALWAYS: `journal_emit.py metadata` derives the reviewed run identity from the computed review bundle manifest and the current worktree identity through the shared changeset-scope primitives, including `branchSlug`, `headSha`, `baseRef`, `baseSha`, `configDigest`, `scope`, and timestamps; `scope.changedFiles` and `scope.reviewInputSha256` match the manifest for the exact diff bundle the reviewer examines, and `journal_emit.py run-completed` records those fields in the terminal `com.outcomeeng.spx.journal.run.completed` event, deriving its status from the streamed event prefix ([test](tests/test_review_journal_emit.mapping.l1.py))
- ALWAYS: `Finding.rule` is a non-empty string whose form is a path-style citation into an existing rule in the spec-tree or skill ecosystem — `spx/<path>:<MUST\|NEVER\|ALWAYS\|SCENARIO\|MAPPING\|CONFORMANCE\|PROPERTY\|COMPLIANCE>:<n>`, a path to a spec-tree ADR/PDR, `plugins/<plugin>/skills/<skill>/SKILL.md:<rule-slug>`, or an equivalent stable identifier. `rule` is never a free-form description, a required-action string, or a tracking-location string ([test](tests/test_review_result.scenario.l1.py))
- ALWAYS: `Finding.rule` cites a rule that actually exists at the referenced location — the review prompt instructs the model to populate `rule` from rules declared in the loaded context, never to invent a citation ([eval](evals/judgment-grounding/eval.toml))
- ALWAYS: the review prompt requires standards findings to cite rule text the reviewer located and read in the repository under review or a governing loaded skill, treats rules recalled from system prompts, user/global instructions, prior sessions, or training as invalid citations, and drops findings whose candidate rule cannot be located ([audit])
- ALWAYS: the wrapper agent at `plugins/spec-tree/agents/changes-reviewer.md` declares `model: sonnet`, `tools: Bash, Read, Skill`, and `skills:` listing `spec-tree:review-changes` ([audit])
- ALWAYS: the wrapper agent streams the run live through the `journal_emit.py` per-event subcommands — appending each finding the instant it is raised through `journal_emit.py finding-reported`, whose per-finding parse is the validity gate before the append — and treats a non-zero parse exit as a re-emit signal — the agent never hand-validates JSON it just emitted, per the shared verification contract in `spx/21-spec-tree.enabler/16-verification.enabler/verification.md` ([eval](evals/wrapper-protocol/eval.toml))
- ALWAYS: the verification skill emits a `blocking` finding asserting absence of a file or fact only when the diff itself contains the deletion or omission — the verification skill does not hallucinate missing artifacts it cannot observe ([eval](evals/judgment-grounding/eval.toml))
- ALWAYS: finding `severity` matches the rubric in `plugins/spec-tree/skills/review-changes/references/review-prompt.md` — `blocking` for merge-safety defects, `debt` for real defects that do not jeopardize merge safety; the author judges whether each `debt` is fixed in the PR or tracked out of scope, per `spx/15-merging.pdr.md` ([eval](evals/severity-classification/eval.toml))
- ALWAYS: each pass against a given changeset surfaces every finding the changeset exhibits in that single pass — there is no cross-pass continuity, and a finding missed on this pass has no second chance unless the diff itself changes ([review])
- ALWAYS: the review streams its events live — it opens the journal, appends a scope-entered event, appends a scope-advanced event as it examines each changed file, appends a finding-reported event the instant it raises each finding, appends a run-completed event, and seals — never building one batch of events from a finished review, per `spx/21-spec-tree.enabler/16-verification.enabler/13-run-journal.adr.md` ([review])
- ALWAYS: after sealing the review journal run, the skill reads the sealed event prefix and renders the result through `journal_emit.py render`, surfacing the run token, the per-severity finding count (`BLOCKING: <n>, DEBT: <n>`), and the rendered surface when any finding is present — so a direct skill invocation yields the findings the caller must act on, not only a persisted journal run ([review])
- ALWAYS: known-clean diffs yield zero `blocking` findings and known-broken diffs yield at least one `blocking` finding at the per-eval threshold — the suite gate value `0.85` governs CI pass/fail, not a single trial ([eval](evals/findings-direction/eval.toml))
- NEVER: any script under `plugins/spec-tree/skills/review-changes/scripts/` imports a third-party package, depends on `uv` at runtime, or imports any `outcomeeng_*` module — stdlib only per the Plugin Portability Constraints in `AGENTS.md` ([test](tests/test_reviewing_changes.compliance.l1.py))
- NEVER: the wrapper agent writes review artifacts outside `spx journal`; durable review state is the sealed review journal prefix, per the shared verification contract in `spx/21-spec-tree.enabler/16-verification.enabler/verification.md` ([eval](evals/wrapper-protocol/eval.toml))
- NEVER: the review prompt is embedded inside `SKILL.md` or any script — the prompt is one standalone markdown file at the declared reference path so swapping the prompt does not require touching code ([audit])
- NEVER: a script under `plugins/spec-tree/skills/review-changes/scripts/` renders a human-readable review surface from the review-result JSON payload — the surface is rendered only from the sealed run-journal event prefix, so the journal is the review's sole source of truth ([test](tests/test_reviewing_changes.compliance.l1.py))
