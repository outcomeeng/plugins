# Closure

PROVIDES the precondition deciding whether a session may close at all, the reflection that anchors it to a node, and the persistence that makes its work recoverable from origin
SO THAT a closing agent
CAN establish that no do-able work remains and that everything the closure points at is reachable by a cold context

## Assertions

### Compliance

- ALWAYS: from a linked (pool) worktree, `/handoff` invokes `spx session handoff` only after detaching the worktree to the `origin/<default-branch>` tip — the CLI refuses a linked worktree in any other state — and leaves the worktree detached afterward so the released work branch stays unoccupied for another worktree or agent to claim; the committed branch ref carries the work forward, not the worktree checkout ([audit])
- ALWAYS: `/handoff` writes a session document only when the working tree is clean and the work branch is published to origin — its `@{upstream}` exists and is not ahead — otherwise it runs `/commit-changes` and pushes the work branch first; it passes the work branch to `spx session handoff` as the explicit work-branch ref so the recorded `git_ref` is the work branch, and `/pickup` fetches and checks out the branch `git_ref` names, reading in place when `git_ref` is the default branch or a commit SHA, per `spx/21-spec-tree.enabler/76-sessions.enabler/13-handoff-persistence.adr.md` ([audit])
- NEVER: `/handoff` emits a chat-only or local-only session document, or satisfies the persistence precondition by running from a different already-clean worktree while the work worktree keeps its branch — that anchors `git_ref` at unrelated state and leaves the branch occupied so `/pickup` cannot claim it; the skill frames the precondition by what breaks so it is understood, not merely prohibited ([audit])
- ALWAYS: the `/handoff` skill reads PLAN.md and ISSUES.md from the active node during reflection and anchors the session document to that node so the next agent loads them via `/contextualize` — coordination-note content is pointed at through the node, not copied into the session file, and never silently omitted ([audit])
- ALWAYS: `/handoff` runs only when the session is genuinely over — the user's stated goal is met with no continuation remaining, or continuation by the agent is impossible (the user halted the work, the context is exhausted, or an external blocker prevents the next action); while do-able in-scope work remains (a pending `PLAN.md` item, a `spx/EXCLUDE` entry, a declared-but-unimplemented assertion, or a named-but-unbuilt part of the user's stated goal), the session does not close and `/handoff` is not invoked — a merge, a passing gate, or a freshly written coordination note is never a license to stop, per `/understand` `<closing_protocol>` ([audit])
- ALWAYS: a branch carrying committed changes ahead of its resolved base is continuation work for default-branch tasks, even when the working tree is clean and local gates have passed; status assessments may report local evidence, then continue through `/merge` unless the user explicitly limited the task to local-only work or an explicit lifecycle gate blocks continuation ([eval](../../../76-merge.enabler/evals/local-completion-boundary/eval.toml))
- ALWAYS: `/handoff` treats every encountered `PLAN.md`, `ISSUES.md`, `spx/EXCLUDE` entry, and declared-but-unsatisfied assertion as a closure blocker while the agent can still act — it fixes or reconciles all in-scope coordination notes in the same session, fixes safe local coordination-note defects even when they sit outside the original scope, and asks the operator only for non-blocking ownership or scope decisions rather than converting the note into a session file ([audit])
- ALWAYS: treat a persisted node-local PLAN.md or an unresolved ISSUES.md entry on an anchored node as evidence that closure is blocked unless continuation by the agent is impossible; a coordination note that carries no future work is removed during closure, never kept while the session file is skipped, and a small imperfection is fixed in-session rather than deferred into a note ([audit])
- ALWAYS: when `/handoff` cannot anchor work to a concrete node, the anchor workflow presents `Product-level operations` as the product-domain-neutral option for work that changed operational state or product-wide guidance rather than a node-local spec ([audit])
