# Pickup

PROVIDES the resumption side of session continuity — reconciling a session document's recorded claims against current state, then loading the node it anchors and presenting an evaluated continuation proposal
SO THAT an agent claiming a session written by another context
CAN resume from repository-supported state with every recorded claim reconciled before use

Claim reconciliation and the resumption flow it feeds are governed by the children below. `spx/21-spec-tree.enabler/76-sessions.enabler/28-pickup.enabler/20-claim-verification.adr.md` decides the reconciliation mechanism. Under the coordination overlay declared in `spx/21-spec-tree.enabler/76-sessions.enabler/sessions.md`, the same resumption reads a Change instead of a session document and follows the claim transition in `spx/21-spec-tree.enabler/76-sessions.enabler/21-change-coordination.pdr.md`.

## Assertions

### Compliance

- ALWAYS: under `spx/local/coordination.md`, `/pickup` claims a Change by reading and validating canonical Product, Maturity, Status as Available, and empty assignee state; adding the assignee; posting the earliest `Claim:` comment since the latest release with the agent session id; cleaning a losing claimant's account only when it differs from the winner; letting the winner remove another assignee only when that account's later losing Claim proves its origin; writing Status as Claimed; and verifying the three project fields, the winning account as the sole assignee, and the unchanged earliest Claim before executing an Activity — one account's sessions cannot be told apart by assignee alone ([audit])
- ALWAYS: under `spx/local/coordination.md`, before claiming an existing open, unassigned Change whose canonical Product, Maturity, or Status is absent or whose body begins with legacy metadata, `/pickup` reconstructs every absent value from unambiguous issue and project history, writes and verifies all three canonical fields, removes and verifies removal of only the legacy metadata line, and then applies the normal Available-state claim precondition; unresolved or contradictory history stops before mutation ([audit])
- ALWAYS: under `spx/local/coordination.md`, `/pickup` stops as `owned_elsewhere` when the Change is closed, held by another account or session, has a non-Available Status, or belongs to another Product; a failed write or mismatched readback stops the transition with completed writes, failed operation, and observed state and performs no later mutation ([audit])
- ALWAYS: under `spx/local/coordination.md`, `/pickup` routes by Maturity read from the Changes project field — refinement through `/interview`, `/slice`, and `/verify` below Executable, with Framed and Sliced set only on human approval — and executes an Activity only from an Executable Change whose Frame (Nodes, Assertions, Decisions), blockers, and lineage it has validated against current truth, continuing from the newest Handoff's Next Activity ([audit])
- ALWAYS: under `spx/local/coordination.md`, `/pickup` turns a legacy queue file into one Proposed, Available Change carrying the whole file verbatim as received input without Product, Maturity, Lifecycle, or Status body metadata, archiving the file only after the issue, project item, canonical fields, and empty assignee state are verified ([audit])
- NEVER: `/pickup` executes an Activity of a Change below `Executable`, or presents a `next_step`, plan item, or note entry from received input as the recommended action — the Frame's Decisions and Assertions define the work ([audit])
- ALWAYS: `/pickup` brings the checkout current before presenting any session detail or coordination note, for every `git_ref` kind (feature branch, default branch, or commit SHA) and not only inside `/contextualize`, so no recorded claim is read against a stale checkout, per `spx/21-spec-tree.enabler/76-sessions.enabler/13-handoff-persistence.adr.md` ([audit])
- ALWAYS: `/pickup` invokes `/understand` immediately before its first product-content access — the coordination-note path check under `spx/` when the session names a node, otherwise the `/contextualize` invocation for the node the operator names — and not before the claim, session presentation, checkout, base sync, or claim reconciliation, per `spx/21-spec-tree.enabler/76-sessions.enabler/21-compact-continuity.pdr.md` ([audit])
