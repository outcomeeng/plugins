# PLAN: Build the `diagnose` environment-doctor skill

This node governs the `diagnose` skill — a portable environment doctor for any spec-tree / spx environment. The spec declares the first slice; this note tracks the remaining authoring work and the deferred checks. Coordination only; the spec and its `[eval]`/`[audit]` evidence are the truth.

## Resolved decisions

- **Architecture — deterministic engine in `spx diagnose`, thin invoker skill.** `spx/21-spec-tree.enabler/79-diagnostics.enabler/13-diagnose-engine.adr.md` governs: the diagnose deterministic pipeline (gather, verdict classification, aggregation) lives in the `spx` CLI as `spx diagnose`, tested there and consumed as a trusted third party; the shipped skill is a thin invoker that runs `spx diagnose`, relays the report verbatim, and adds remediation judgment on a non-healthy verdict; a plugin-shipped declarative manifest (spx floor, marketplace identity, expected plugins, check set) is the plugin→spx contract. This supersedes the prior "thin skill classifies in its body / no `spx` CLI subcommand" decision — the dogfood proved the classification has outgrown light orchestration, the exact trigger `spx/12-shipped-scripting.adr.md` and the node's own `[audit]` name for extraction into the `spx` CLI.
- **First slice — seed + `spx` reachability/version.** The `SessionStart`-hook session-environment check (working / identity-only / silent no-op) plus the `spx`-on-PATH check that reports the installed version verbatim. Heavier checks were deferred to follow-up slices.
- **Version-floor source and shape.** `spx/21-spec-tree.enabler/79-diagnostics.enabler/15-version-floor.adr.md` governs the floor's single source of truth (`REQUIRED_SPX_VERSION`), build-render, and no-drift invariant. Under `13-diagnose-engine.adr.md` the floor's render target moves from skill prose to the diagnose manifest and the comparison runs inside `spx diagnose`; the single-source/build-rendered/no-drift invariant carries forward. The render-target update to `15-version-floor.adr.md` lands with the rewire (below), not before — until `spx diagnose` publishes, the floor is rendered into the shipped skill as `15-version-floor.adr.md` currently states.

## Deferred build (gated on publish-before-depend)

`13-diagnose-engine.adr.md` declares target product truth; depending on `spx diagnose` from the shipped skill is blocked until an `@outcomeeng/spx` release provides it and the product floor is advanced. The sequence (steps 1 and 3 are different repositories; step 2 is the seam):

1. **`@outcomeeng/spx`** — build `spx diagnose` (gather → classify → aggregate → emit; `--manifest <path>`, `--format json|text`; per-check `{name, verdict, bucket, readings, remediation}` + overall verdict folded broken > unknown > degraded > healthy; exit code keyed to the overall verdict; the marketplace-install check shells out to `claude plugin` / `codex plugin`, skipping an absent surface). Test it there with `[test]`/pytest, fixing the dogfood's offered-vs-enabled flaw by judging the manifest's enabled set. Publish to npm.
2. **Floor advance** — bump `REQUIRED_SPX_VERSION` (`outcomeeng/validation/spx_version.py`) and the CI `SPX_VERSION` pin (`.github/workflows/check.yml`) to the published release, per the publish-before-depend gate.
3. **Rewire this repo** — ship the diagnose manifest inside the plugin tree (floor build-rendered); collapse `diagnose/SKILL.md` to a thin invoker (guard `spx` ≥ floor with a `diagnose` subcommand, run `spx diagnose --manifest … --format json`, relay verbatim, reason remediation on a non-healthy verdict); migrate `diagnostics.md` evidence — the five per-check `[eval]` classification suites retire (the classification is `[test]` in the `spx` repo), one `[eval]` covers the skill's relay + remediation behavior, and the manifest gets a `[test]` (parses, declares the rendered floor, names the right marketplace/plugins); update `15-version-floor.adr.md` to the manifest render target.

A future surface still grows the report by extension per the node's `<extending>` model; once the engine is in `spx diagnose`, a new check is a new verdict table in the CLI, not new skill prose.
