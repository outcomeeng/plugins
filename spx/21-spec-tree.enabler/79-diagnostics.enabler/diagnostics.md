# Diagnostics

PROVIDES a portable environment-diagnostics capability — the `diagnose` skill — that runs a sequence of named health checks over a spec-tree / spx environment and reports a per-check verdict with a remediation hint
SO THAT a user or agent working any spec-tree product
CAN self-diagnose a misconfigured environment without recalling and typing the underlying interrogation by hand

The capability orchestrates surfaces every consumer already has — the `spx` CLI, the harness session environment, and the install state — and carries no heavy diagnostic logic of its own; a check that outgrows light orchestration extracts into the `spx` CLI per `spx/12-shipped-scripting.adr.md` rather than accreting in the shipped skill. Each check is an independent named diagnostic, so checks are added by extension without restructuring the existing report. The first checks cover the `SessionStart`-hook session environment — the round-trip proven by `spx/21-spec-tree.enabler/13-agent-environment.enabler` — `spx` reachability and version, and the git worktree layout and occupancy.

## Assertions

### Compliance

- ALWAYS: the session-environment check classifies the session as working, identity-only, silent no-op, or — when the readings are inconsistent, the current worktree's status is stale, or a command errors — unknown, from the agent session identity, the worktree-claim flag, and the `spx worktree status` round-trip, and reports not-applicable on a runtime that ships no spec-tree `SessionStart` hook, pairing each verdict with a remediation hint ([eval](evals/session-environment-check/eval.toml))
- ALWAYS: the spx-reachability check classifies `spx` as reachable — reporting its resolved path and version verbatim — or unreachable from its PATH resolution, or unknown when the probe errors, pairing each verdict with a remediation hint ([eval](evals/spx-reachability-check/eval.toml))
- ALWAYS: the worktree-pool check classifies the git worktree layout as compliant (a lone working tree or a bare-repository pool with no stale claims), stale-claims when a worktree's occupancy is stale, or non-compliant when linked worktrees attach to a non-bare repository, from `git worktree list` and the `spx worktree status` occupancy of each worktree, and unknown when a command errors, pairing each verdict with a remediation hint ([eval](evals/worktree-pool-check/eval.toml))
- ALWAYS: the session-store check classifies the `.spx/` session store as consistent (the store reads and every doing session's backing worktree is occupied) or orphaned-claims (a doing session whose `git_ref` worktree is stale or absent), from `spx session list` joined to the `spx worktree status` occupancy backing each doing claim, and unknown when a command errors, pairing each verdict with a remediation hint ([eval](evals/session-store-check/eval.toml))
- ALWAYS: the marketplace-install check classifies the methodology marketplace's install state — across the Claude and Codex plugin surfaces — as installed (each present surface has the marketplace registered and every offered plugin installed, enabled, and at the offered version), drifted (registered, but a plugin is missing, disabled, or below the offered version), or unregistered (a present plugin surface lacks the marketplace registration), from each surface's plugin CLI joined offered-against-installed, degrading to not-applicable when neither surface exposes a plugin CLI and unknown when a command errors, pairing each verdict with a remediation hint ([eval](evals/marketplace-install-check/eval.toml))
- ALWAYS: the skill aggregates its checks into one report carrying a named verdict per check and an overall verdict ([eval](evals/diagnostic-report/eval.toml))
- ALWAYS: the shipped skill reasons only about surfaces the runtime exposes — the `spx` CLI, harness environment variables, and install state — degrading a check to not-applicable where its surface is absent rather than misclassifying, and names no product-internal spec-tree node address ([audit])
- ALWAYS: each check is an independent named diagnostic carrying its own verdict and remediation, so a check is added by extension without restructuring existing checks ([audit])
- NEVER: the shipped skill carries heavy, test-bearing diagnostic logic of its own — light orchestration of existing `spx` and harness surfaces stays in the skill, and a check that outgrows it extracts into the `spx` CLI per `spx/12-shipped-scripting.adr.md` ([audit])
