# Installation State

Persistent marketplace refresh preserves the selected plugin set and activation through native update operations, using the canonical `outcomeeng/plugins` source. Empty selection bootstraps only `spec-tree` with a warning and disabled activation where none is declared. Isolated verification installs committed catalog selections from the invocation checkout in disposable homes.

## Rationale

Selection declarations survive missing caches and interrupted installation, while activation remains the operator's choice. Rejecting source mismatches and retaining unexpected writes for diagnosis avoids destructive source replacement and compensating configuration restoration.

## Product properties

1. Persistent selection is bounded and ordered by each agent's committed marketplace catalog. Claude Code supplies its installed `outcomeeng` inventory at project or local scope in the invocation checkout for bootstrap, and every project- or local-scope `outcomeeng` install record it reports on the machine for refresh: each record whose plugin the committed catalog carries, whose project path is an existing directory, and whose project declares no noncanonical marketplace source is refreshed through the native plugin update from its own project path, so every Claude Code session on the machine starts and reloads at the canonical source. A record whose plugin the catalog does not carry, whose project path is no existing directory, whose scope is neither project nor local, whose own project settings register the marketplace from a noncanonical source, or whose settings cannot be read is reported and left unchanged. The invocation checkout's own declared source is validated before any plan: a noncanonical declaration or unreadable settings stop the run. The machine registry's own marketplace entry is validated against the canonical source before any record is refreshed. Codex selection comes from the plugin keys declared in the selected home's configuration, including disabled entries and entries whose caches are absent; merged product overrides and cache presence do not choose that home-wide set. Every nonempty selection contains `spec-tree`. An empty selection supplies only `spec-tree` and a warning to choose additional plugins; an empty Codex home receives it disabled. Claude Code bootstrap preserves any declared project activation and defaults an undeclared bootstrap plugin to disabled.
2. Persistent preflight rejects the complete run before mutation for a noncanonical registered source or Claude Code user-scope collision, identifying the observed source or colliding settings path and required explicit repair. Missing registration, snapshot, and selected-plugin cache are recoverable without widening selection or changing activation, including after interruption and at an unchanged marketplace revision. Every selected published plugin is refreshed, including disabled plugins; explicitly enabled home entries remain enabled. Post-run selection or activation drift in the invocation checkout or selected home fails without restoring an earlier snapshot or issuing compensating activation writes. Other recorded checkouts receive only native updates, which write no activation entry and carry no activation postcondition. Established absence of a selected plugin from the canonical marketplace is reported separately as pending publication, preserving prior owned definitions and allowing the other selected plugins to continue; any other failure stops subsequent operations.
3. Isolated verification registers the invocation checkout and exercises full catalogs, generated valid subsets containing `spec-tree`, and invalid subsets omitting it. An absent declared plugin is terminal. Installation and session state resolve beneath caller-selected disposable homes; native subscription discovery alone may read and natively refresh the selected saved-login file under `spx/32-distribution.enabler/21-installation.enabler/15-installation-architecture.adr.md`. Persistent registration, caches, and definitions remain unchanged.

## Verification

### Testing

- ALWAYS: persistent selection uses Claude Code's inventory recorded for the invocation checkout at project or local scope and Codex's selected-home plugin declarations, including disabled entries, bounded and ordered by the corresponding committed catalog. ([mapping])
- ALWAYS: trusted product `.codex/config.toml` may enable chosen skills over disabled home defaults, while persistent Codex inspection and execution remain independent of product overrides. ([compliance])
- ALWAYS: empty persistent selection supplies only `spec-tree` with a warning, disabled where no activation is declared; an empty Codex home declares `spec-tree` disabled. ([compliance])
- ALWAYS: refresh uses native operations that preserve the selected set and activation, including disabled plugins, and verifies both after execution for the invocation checkout and the selected home; a mismatch is reported without restoring an older configuration snapshot. A recorded checkout elsewhere receives the native update alone, which writes no activation entry, so it carries no postcondition. ([compliance])
- NEVER: refresh resets an existing explicitly enabled home entry to the disabled default. ([compliance])
- NEVER: an existing noncanonical marketplace source reaches a state-changing operation; the diagnostic identifies the source and requires explicit repair. ([compliance])
- ALWAYS: recovery of a missing registration, snapshot, or selected plugin cache preserves the declared selection and activation, including a retry after interrupted installation. ([compliance])

- NEVER: a nonempty persistent agent selection omitting `spec-tree` reaches a state-changing command ([compliance])
- ALWAYS: persistent installation reports established canonical-source absence as pending publication and continues with the remaining selected plugins until completion or the first other failure, while isolated verification treats the same absence as terminal at that plugin's operation ([compliance])
- NEVER: persistent installation mutates Claude Code user scope; a user-scoped `outcomeeng` marketplace registration stops the run before its first state-changing command ([compliance])
- ALWAYS: persistent Claude Code refresh maps every reported project- or local-scope `outcomeeng` install record for a cataloged plugin with a project path that is an existing directory and no noncanonical project source to one native plugin update at that record's scope and project path, reports a record whose plugin the catalog does not carry, whose project path is no existing directory, whose scope is neither project nor local, whose own project settings register a noncanonical source, or whose settings cannot be read without a command, reads a project's declared source in Claude Code's own precedence order with the local document over the project document, and never substitutes a reinstall for the update ([mapping])
- ALWAYS: isolated verification confines `HOME`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, and `CODEX_SQLITE_HOME` beneath caller-selected disposable state; subscription discovery may read and natively refresh only the selected saved-login file, leaving persistent installation state unchanged ([compliance])
- ALWAYS: installation derives marketplace membership from committed per-agent catalogs ([mapping])
- ALWAYS: marketplace-install diagnosis bounds expected plugin membership by the checkout's committed per-agent marketplace catalogs; shipped diagnostic output embeds no expected plugin set ([compliance])
- ALWAYS: isolated installation verifies every catalog plugin, a generated valid subset containing `spec-tree`, and a generated invalid subset omitting `spec-tree` in disposable homes without mutating persistent state ([compliance])
