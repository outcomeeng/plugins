# Repository Marketplace Installation Architecture

Marketplace installation uses a Python ports-and-adapters boundary with persistent and isolated modes. Committed agent-harness declarations and read-only installed-plugin observations parse into an immutable preflight report and installation plan, orchestration executes the accepted plan through agent-specific adapters implementing shared Protocols, and the CLI entry point binds the real subprocess runner. Persistent preflight inspects each selected agent state before mutation, validates a nonempty installed subset contains `spec-tree`, derives empty state as the `spec-tree` bootstrap selection with a warning, and orders selected names through that agent's committed catalog. Persistent source reconciliation begins only after every selection validates. Persistent planning validates Claude Code's user/project scope boundary, derives Codex source state from the selected `CODEX_HOME`, and plans the generated Codex agent definitions of every selected plugin into that home's `agents/` directory. Isolated planning redirects every agent state root beneath caller-selected disposable state, registers the invocation checkout, and accepts catalog-bounded selections for full-catalog and subset verification. Orchestration recognizes one non-terminal failure: a persistent-mode selected plugin install or enable whose agent CLI reports the plugin absent from the marketplace, which orchestration records as pending publication and passes over.

Codex agent-home placement uses a marketplace ownership record keyed by destination path, owning plugin, and installed-content digest. A plugin's shipped placement entry point may create, replace, or prune only that plugin's recorded definitions; repository installation composes every selected plugin's planned entries from the committed catalog and performs the distinct marketplace-wide reconciliation, so a recorded definition whose plugin leaves the selection is pruned with the skills it invokes. A recorded definition is replaceable or removable only while its on-disk digest still matches the record; an unrecorded destination whose bytes already equal the desired shipped content — the artifact of a run interrupted before its ownership-record write — is adopted into the record without a mutation, and any other unrecorded or modified destination is a collision left untouched. Before any marketplace, plugin, agent-definition, or ownership-record mutation, planning compares the checkout agent definitions of plugins whose invoked skill content the selected home installation supplies — the scope split `spx/12-marketplace-state.adr.md` defines, which leaves a checkout that itself carries the invoked skill content outside this comparison — with the generated definitions for that home: byte-identical plugin copies receive a directed-removal report, changed or unrecognized copies receive a shadowing-collision report, and either class rejects the complete plan as the scope split governed by `spx/12-marketplace-state.adr.md`.

Installed subagent discovery uses one fresh non-interactive Codex session against a disposable installation. A typed authentication selection chooses subscription, API, or workspace-token mode; local selection defaults to subscription and CI requires an explicit mode. Credential presence never selects a mode or permits fallback to another billing mode.

Subscription mode resolves the original selected `CODEX_HOME` before redirecting the child environment. After installation, only the disposable home's `auth.json` links to the selected existing file-backed ChatGPT login. The child uses the file credential store and the native CLI owns refresh and persistence through that link. A compatibility preflight with fabricated credentials in temporary homes verifies write-through behavior before the saved login is exposed. Keyring-only, malformed, missing, or non-ChatGPT saved credentials fail with an actionable diagnostic.

Participating verification processes serialize access to the canonical credential file for the credential-use interval within the probe's timeout. File identity, account identity, and link destination are checked before and after use. A detected replacement or account switch fails without restoration or automatic retry. Unrelated CLI processes retain native refresh concurrency semantics; the harness neither controls their locks nor promises to prevent their races. The harness performs no OAuth exchange, saved-home login or logout, or temporary credential-copy restoration.

API and workspace-token modes require `OPENAI_API_KEY` and `CODEX_ACCESS_TOKEN`, respectively, and provision only the disposable home through native login with the credential on stdin. Unrelated credential variables are removed from child environments. One injected Protocol owns process invocation with array arguments, explicit environment, working directory, stdin, and timeout. Captured output and timeout diagnostics are scrubbed against both initial and refreshed credentials before an observation or exception is exposed.

The fresh session reports available subagent names in a harness-owned JSON schema. Its read-out must include the canonical names whose definitions the same installation placed in the disposable home. Installation, login, and session failures are terminal. The harness exposes observations; linked tests own the comparison and every pass/fail predicate.

Native profile-execution evidence is a matrix over the selected agent harnesses and all Standard, Strong, and Fast profiles owned by `outcomeeng.distribution.profiles.AGENT_PROFILES`. An optional --target selects one supported harness; omission selects every supported harness. A row derives its complete native configuration from that registry and materializes its native probe definition beside the installed skill content in one disposable state root. The profile-execution entrypoint extends the repository-installation harness and owns the row lifecycle: isolated installation, configuration capture, native-definition loading capture, parent-session configuration capture, one native subagent invocation, result capture, credential scrubbing, and cleanup. It exposes no verdict. The `just verify-native-profile-execution <artifact-directory>` recipe is the sole execution boundary for that entrypoint and retains one configuration artifact, one loading artifact, and one result artifact for each `<harness>-<profile>` row beneath the caller-selected artifact directory. The configuration artifact identifies the profile-probe definition derived from the central profile owner. The loading artifact identifies the definition discovered from disposable state. The result artifact identifies the parent session separately from its one child invocation and records the child's sanitized result: Claude Code supplies forwarded stream events carrying `parent_tool_use_id`; Codex supplies the parent thread identity through exec JSONL, then lists that parent's active and archived spawned children through the native app-server interface with an explicit subagent source filter and complete pagination. Exactly one listed child permits one thread/read request in the same disposable state. Missing, multiple, malformed, or unrelated child identities produce unusable evidence. Listing pages and the child response are retained. The Codex child-thread record supplies its configured role, recorded model and effort, and completion evidence. Recorded model and effort are configuration evidence, not per-turn execution telemetry. Exec spawn events and parent prose establish none of those properties. A main-session `--agent`, `--model`, or `--profile` selection is retained only as parent-session configuration and never substitutes for the native subagent invocation. Each artifact identifies its row and contains no credential value. The one selected credential channel for a row reaches only the corresponding native CLI boundary. Credential absence, loading failure, or an unusable session result records that row as failed evidence, without a retry, alternate credential channel, profile substitution, or alternate launch mechanism.

## Rationale

Separating declaration parsing, installed-state inspection, scope and collision inspection, validation, plan construction, and external CLI execution makes the exact selected plugin set and every mutation target inspectable before the first write. Persistent mode uses each agent's supported ownership model: Claude Code project scope and Codex's selected home. Catalog ordering gives stable command plans without turning catalog membership into automatic installation. The content-bound ownership record distinguishes files a prior marketplace operation may update from foreign or locally modified files, while the committed catalog gives the repository installer authority to reconcile removed agents and plugins across the marketplace without granting one plugin control over another plugin's namespace; deriving the desired definition set from the selection keeps every placed definition beside skills the same run installed. Rejecting the whole plan on a checkout scope split prevents skill refresh from advancing underneath a shadowing checkout definition. Isolated mode establishes full and subset behavior at the real CLI boundary with persistent installation state isolated and saved-login access limited to the declared credential exception. The subagent-discovery probe exists because the co-location decision rests on the agent loading subagent definitions from its selected home; the app-server protocol lists no user-scope subagent definitions, so a real tool-backed session is the only surface that can answer, and a schema-declared structured result keeps that answer machine-checkable rather than model prose. Deriving the expected set from the same run's placement keeps the discovery oracle independent of the session. A link to the selected credential file lets native refresh persist without introducing a stale temporary-copy restoration; copying refreshable bundles into independent homes would require a second persistence mechanism. The behavior under test is the agent's deterministic subagent registry, and the model inside the probe session is only its schema-constrained read-out channel — the agent exposes that registry through no other surface — so the probe's evidence is a deterministic test scenario over structured output rather than an eval over model judgment. Controlled runners used under `/test` Stage 5 Failure simulation expose first-failure behavior that a successful real install cannot produce reliably, while recording collaborators used under `/test` Stage 5 Interaction protocols expose command order and shape.

## Invariants

- Installation operations preserve their declaration-derived order.
- Every persistent installed-plugin inspection completes and every selected subset validates before source reconciliation or plugin mutation begins.
- An empty persistent installed set maps to `spec-tree` plus one warning; every nonempty set maps to itself only when it contains `spec-tree`.
- Catalog ordering never adds an unselected plugin to a persistent plan.
- The first failed operation is terminal for one installation run, other than a persistent-mode plugin operation reporting the plugin absent from the marketplace, which the run records as pending publication and continues past.
- Only a persistent plan admits that pending-publication carve-out; an isolated plan registers the checkout as the marketplace, so the same absence there is terminal.
- A persistent plan exists only after Claude Code user-scope collision detection and canonical project-source validation complete.
- Persistent Codex commands carry the selected `CODEX_HOME` explicitly and never consult repository `.codex/config.toml`.
- Every installation state path used by isolated mode resolves beneath its disposable home; subscription discovery alone may read and refresh the selected saved-login file.
- Every generated Codex agent destination in persistent mode resolves beneath the selected `CODEX_HOME/agents/` directory.
- Every planned overwrite or prune names a marketplace ownership-record entry whose installed-content digest matches the destination's current bytes.
- A plugin placement plan contains only that plugin's recorded definitions; cross-plugin pruning exists only in repository installation's catalog-derived marketplace reconciliation.
- Scope-split and foreign-collision inspection completes before the first marketplace, plugin, agent-definition, or ownership-record mutation.
- Authentication mode is fixed for the run; failed authentication never switches mode.
- The saved-login file is the sole persistent-state exception during subscription discovery.
- Cleanup removes disposable state without traversing the saved-login link.
- Native profile-execution evidence contains exactly one row for each selected harness and central profile, derived from `AGENT_PROFILES` without an independent model, reasoning, or credential inventory.
- Every native profile probe uses a separate disposable state root and invokes one native subagent after isolated installation and native loading complete.
- Every native profile probe retains configuration, loading, and sanitized result artifacts beneath the recipe's caller-selected artifact directory.
- Every Codex native profile probe reads one spawned receiver thread from its disposable state through the native app-server interface and retains its configured role, model, effort, and child completion evidence with the parent-filtered listing and parent thread identity.

## Verification

### Testing

- ALWAYS: explicit authentication modes select their own required credential source and native login mechanism; local default subscription and required CI selection remain independent of credential-variable presence. ([compliance])
- ALWAYS: subscription verification checks native credential write-through compatibility before linking only the saved-login file into disposable state. ([compliance])
- ALWAYS: participating verification processes serialize saved-login use, preserve native refresh writes, and report detected link, file, or account replacement without restoring an earlier copy. ([compliance])
- NEVER: subscription verification migrates a credential store, implements OAuth refresh, or invokes login or logout against the linked home. ([compliance])

- ALWAYS: committed Claude Code and Codex declarations plus selected installation mode are validated at the boundary and converted into frozen typed records before orchestration consumes them ([conformance])
- ALWAYS: persistent preflight parses each agent's read-only plugin listing into a catalog-bounded installed subset before emitting any state-changing command ([conformance])
- ALWAYS: selection validation maps empty state to `spec-tree` plus a warning, accepts nonempty subsets containing `spec-tree`, and rejects nonempty subsets omitting `spec-tree` ([mapping])
- NEVER: persistent plan construction adds a catalog plugin absent from that agent's installed-plugin observation ([compliance])
- ALWAYS: command execution avoids shell interpretation and preserves stdout, stderr, and the exit code in a structured result ([compliance])
- ALWAYS: orchestration reports a failed operation with its agent, plugin when applicable, operation name, and structured command result, then executes no later operation ([compliance])
- ALWAYS: a persistent-mode plugin install or enable whose result reports the plugin absent from the marketplace is recorded as pending publication in the installation report, and every later operation still executes ([compliance])
- NEVER: the pending-publication carve-out applies to an isolated plan, to a non-plugin operation, or to a failure whose result does not report the plugin absent from the marketplace ([compliance])
- ALWAYS: persistent planning rejects a user-scoped Claude Code `outcomeeng` registration before emitting a state-changing command and reports the colliding settings path ([compliance])
- ALWAYS: the isolated harness redirects `HOME`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, and `CODEX_SQLITE_HOME` beneath its disposable home for every agent invocation ([compliance])
- ALWAYS: persistent Codex planning places each generated agent definition beneath the selected `CODEX_HOME/agents/` directory and records its destination, owning plugin, and installed-content digest in the marketplace ownership record ([compliance])
- ALWAYS: plugin placement creates, replaces, or prunes only the invoking plugin's recorded definitions, while repository installation reconciles the complete recorded marketplace set against the current committed catalog ([compliance])
- NEVER: placement overwrites or prunes an unrecorded destination, or a recorded destination whose current digest differs from its installed-content digest ([compliance])
- ALWAYS: reconciliation adopts a present destination whose digest equals the desired shipped digest but which no ownership entry records into the ownership record without a mutation, so a run interrupted before its ownership-record write completes cleanly when re-run ([compliance])
- ALWAYS: a scope-split preflight reports byte-identical checkout copies as directed removals and changed or unrecognized checkout definitions as shadowing collisions, rejecting the complete plan before any mutation in either case ([compliance])
- NEVER: persistent planning infers Codex plugin state from repository `.codex/config.toml`; the selected `CODEX_HOME` and Codex CLI are its state boundary ([compliance])
- Given a disposable installation and an authenticated fresh session, when the session reports available subagent names, then its structured name set contains every canonical name whose definition that installation placed under the disposable home's `agents/` directory ([scenario])
- NEVER: discovery exposes an initial or refreshed credential in a command argument, returned capture, diagnostic, or exception, or silently skips a selected check when credentials are absent ([compliance])

### Audit

- ALWAYS: external agent and lifecycle commands execute through an injected Protocol using array arguments, an explicit working directory, and an explicit environment; the real subprocess implementation is bound only at the CLI composition edge ([audit])
- ALWAYS: the real-agent installation harness owns disposable-home creation, mirrored-checkout setup, environment redirection, dependency checks, and cleanup while exposing observations for linked tests to judge ([audit])
- ALWAYS: the subagent-discovery probe drives the non-interactive Codex session through the injected runner Protocol with an explicit `CODEX_HOME` beneath the disposable home, owns the output schema and the authentication lifecycle, and exposes the parsed subagent name set and command result as observations while the linked test owns every predicate ([audit])
- NEVER: installed subagent discovery is inferred from the presence of subagent definition files under `agents/`, from the app-server protocol, or from free-form session prose — the structured session result is the only discovery evidence ([audit])
- ALWAYS: native profile-execution derives each row's complete configuration from `AGENT_PROFILES`, materializes its probe definition beside its installed skill content in disposable state, and retains configuration, loading, and sanitized result artifacts for independent inspection ([audit])
- ALWAYS: the profile-execution entrypoint records each parent-session configuration separately and makes exactly one native subagent invocation for each harness/profile row; Claude Code records a forwarded child stream event with `parent_tool_use_id`, Codex records the parent thread identity, complete parent-filtered active and archived child listings, and one native app-server child-thread read carrying the configured role, recorded model and effort, and completion evidence, and the entrypoint exposes every result as an observation without a verdict ([audit])
- NEVER: Codex exec JSONL alone establishes the child role or complete native configuration; the matching receiver-thread record from the disposable state supplies that identity evidence, and the profile-execution entrypoint does not infer it from parent-session arguments or assistant output ([audit])
- NEVER: a main-session `--agent`, `--model`, or `--profile` selection serves as evidence that a profile-probe definition loaded or that a native subagent invocation occurred ([audit])
- NEVER: native profile execution retries a failed row, substitutes a profile or launch mechanism, or obtains a credential through a channel other than the row's selected native CLI boundary ([audit])
- ALWAYS: controlled runners are used only under `/test` Stage 5 Failure simulation to expose otherwise unreliable command failures, and recording collaborators are used only under `/test` Stage 5 Interaction protocols to expose command order and shape; both preserve the real Protocol boundary and leave every predicate to the linked test ([audit])
- NEVER: a real-agent harness, Failure simulation controlled runner, or Interaction protocols recording collaborator accepts an expected result, calls an assertion API, or returns a verdict ([audit])
- NEVER: framework mocks or process-global monkeypatching replace an agent CLI, lifecycle command, declaration reader, or subprocess boundary ([audit])
