# Prose

PROVIDES one matched prose surface — structure, text, and audit owned by separate skills — over composed per-kind standards layers
SO THAT skills, agents, and documentation across the marketplace
CAN produce and judge human-facing text in one voice family without selecting among overlapping style skills

The prose plugin exposes three workflow skills mirroring the language triple. `/architect-prose` writes prose ADRs: structural decisions for the prose artifacts a spec node governs, driven by that node and located in the spec tree. `/author-prose` is the prose artifact's sole writer: it takes the kind, composes that kind's standards layers, writes text that complies with the governing ADR, and directs an audit pass. `/audit-prose` is the audit methodology: it takes the kind and judges the artifact; it runs only inside the dispatched `prose-auditor` thin agent. Chat responses to the user route to none of these — the plugin's rendered output style governs them. Operational prose — a code comment, a commit message, an agent-facing instruction — likewise stays outside the prose surface, with the workflow that owns it.

Structure and text have separate owners. A prose ADR carries the artifact set's structural decisions — sections, ordering, and moves, including sequencing across sibling and descendant artifacts — so structural intent never leaks into the artifact as annotation, and the artifact has exactly one writer. `/architect-prose` never writes a prose artifact; `/author-prose` never decides structure against the governing ADR.

The kind is an input to every entry, never a conclusion any skill reaches. Writing precedes the text, so no property of the text is available when authoring begins; judging against an inferred kind confirms text written for the wrong slot as correct, which is the error the surface exists to catch. The caller supplies the kind, a repository may declare a path-to-kind map its owner writes, and an interactive entry with neither asks once from the fixed list.

The kinds are copy (a standalone piece read start to finish), interface (text inside a designed surface), and documentation (a page in a document set). A kind exists only where it carries a rule no other kind carries, and a kind varies on two axes: its structural conventions live as a per-kind layer of `/prose-architecture-standards`, its style overrides as a per-kind layer of `/prose-standards`. Both standards skills are composed-only — reached through the workflow skills, never matched by the harness. Every kind's style layer derives from the shared `/prose-standards` anti-pattern catalog and transcludes the one authored voice canon, so kinds differ in register and composition, never in voice.

Register variation inside one text is carried by rule packs, not by a second kind. A pack declares the observable feature that triggers it and the rules that then bind: numbered steps or imperative procedure trigger the instruction caps, and a table triggers the table-shape rules. Packs fire inside every kind, so a runbook's procedure and an essay's table are each governed wherever they appear, and one text carries exactly one kind.

An audit run reveals its result while it runs, per `spx/15-audit-result-delivery.pdr.md`: `/audit-prose` streams scope progress and each finding — pattern name, catalog category, offending quote, concrete rewrite — through the run journal as the run advances, and the `prose-auditor` agent's final message is the raw run token. A dispatched audit that receives no kind records a blocked outcome and judges no text.

The plugin ships a rendered output style named `prose` whose voice rules and every kind's voice rules render at build time from one authored canon, so no consumer of that voice can drift from another. The output style ships natively inside the plugin's output-style surface; an agent harness without the output-style concept ignores it.

## Assertions

### Compliance

- ALWAYS: `/architect-prose`, `/author-prose`, and `/audit-prose` are the plugin's only workflow skills — `/prose-architecture-standards` and `/prose-standards` declare themselves composed-only and are reached through a workflow skill, never matched directly ([audit])
- ALWAYS: structure and text have separate owners — `/architect-prose` writes a prose ADR in the governing spec node and never writes a prose artifact, and `/author-prose` is the artifact's sole writer, complying with the governing ADR, with structural moves across sibling and descendant artifacts carried as decision content rather than in-artifact annotation ([audit])
- ALWAYS: the kind is supplied to every entry — as a caller argument, from a repository's declared path-to-kind map, or from the one question an interactive entry asks — and no skill derives it from the text, the request, or the destination ([audit])
- ALWAYS: an `/audit-prose` run is produced only in a dispatched verifier context through the `prose-auditor` agent, streams scope progress and each finding — pattern, category, quote, rewrite — through the run journal as the run advances, and ends with the raw run token as the agent's final message; a dispatch with no kind records a blocked outcome and judges no text ([audit])
- ALWAYS: every kind's style layer derives from the shared `/prose-standards` catalog — inherited rules condensed to names, explicit overrides, and kind-specific rules — and the shipped `prose` output style and every kind's voice rules render from one authored canon, so kinds differ in register and composition, never in voice ([audit])
- ALWAYS: a kind carries at least one rule no other kind carries, and register variation inside one text is governed by a rule pack whose trigger is an observable feature of that text ([audit])
- NEVER: text another surface owns is authored or audited through the prose surface, and ownership outranks a supplied kind — a repository- or domain-governed artifact (spec, decision record, `SKILL.md`, coordination note, agent guide) stays with its governing workflow, a chat response is governed by the rendered output style, and operational prose (code comment, commit message, agent-facing instruction) stays with the workflow that owns it ([audit])
