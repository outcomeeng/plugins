## Replace machine-specific process hygiene with a portable silent load waiter

The root [`## Process hygiene`](../AGENTS.md#process-hygiene) policy grew from a machine-specific failure: the harness expected the macOS `pgrep`, while a Homebrew GNU `pgrep` installation behaved incompatibly and contributed to process-ID and file-descriptor exhaustion. The resulting blanket prohibition on sleeping processes generalized that diagnosis into shipped agent guidance. This repository is the least important consumer; the replacement must work from an installed plugin in consumer repositories with unknown layouts and tooling.

**Resolution shape**: replace agent-owned load arithmetic, timer selection, and repeated checks with one portable, standard-library-only Python process shipped inside the plugin runtime. The agent invokes the helper once and follows its exit status. The helper owns observation, interval selection, sleeping, rechecking, and the readiness decision.

The helper contract is:

- Read the host's 1-, 5-, and 15-minute exponentially weighted load averages through `os.getloadavg()` and normalize them with `os.cpu_count()`. Treat an unavailable load average or CPU count as an unsupported platform instead of calling `uptime`, `nproc`, `sysctl`, `pgrep`, or repository-local tooling.
- Use all three load averages to distinguish a transient spike from sustained or rising pressure and to calculate each wait interval. Every wait interval is at least 60 seconds. Continue waiting and rechecking inside the same process until the readiness rule permits heavy work; impose no arbitrary total-wait ceiling.
- Remain completely silent while waiting. Immediately before exit, emit exactly one machine-readable JSON document containing the initial and final observations, total elapsed wait, wait-cycle count, and readiness result. Emit no progress lines, heartbeats, or periodic output.
- Exit zero only when readiness is achieved. Use a nonzero exit for an unsupported platform, interruption, or internal failure, with the final JSON identifying the terminal result.
- Spawn no subprocesses, create no additional files, and keep one process with a stable, small file-descriptor footprint and negligible CPU use for the duration of the wait.
- Carry no dependency on this repository's `just` recipes, `outcomeeng_*` packages, paths, language choices, or spec tree. Ship identically into the generated Claude Code and Codex runtime trees under the Python support and standard-library rules in [`spx/12-shipped-scripting.adr.md`](12-shipped-scripting.adr.md).

The implementation must establish the governing decision before lower layers adopt the behavior. Amend [`spx/13-plugin-and-runtime-conventions.adr.md`](13-plugin-and-runtime-conventions.adr.md), whose global no-polling and no-long-lived-process invariants currently contradict a bounded-resource waiter, and reconcile [`spx/15-agent-tools.pdr.md`](15-agent-tools.pdr.md), which requires each exposed wait to have an exact command and return condition. Sweep every duplicate wait constraint, including [`src/plugins/spec-tree/skills/task-tracking-standards/SKILL.md`](../src/plugins/spec-tree/skills/task-tracking-standards/SKILL.md), [`spx/16-interfaces.enabler/21-browser.enabler/15-transport.adr.md`](16-interfaces.enabler/21-browser.enabler/15-transport.adr.md), [`spx/15-validation.enabler/65-gate.enabler/gate.md`](15-validation.enabler/65-gate.enabler/gate.md), [`spx/21-spec-tree.enabler/13-infrastructure.enabler/21-github-actions.enabler/32-workflow-observability.enabler/workflow-observability.md`](21-spec-tree.enabler/13-infrastructure.enabler/21-github-actions.enabler/32-workflow-observability.enabler/workflow-observability.md), and [`spx/21-spec-tree.enabler/54-aligning.enabler/ISSUES.md`](21-spec-tree.enabler/54-aligning.enabler/ISSUES.md). Reconcile each declaration that governs the new helper and remove superseded duplicates.

Verification covers falling, rising, and persistently high synthetic load sequences; the 60-second minimum; normalization by CPU count; readiness and terminal error exits; complete silence before the final JSON; one-document output; zero subprocess and file creation; and identical generated runtime delivery. The tests use controllable load and clock seams so verification never waits for wall-clock minutes.

After the helper, governing decisions, guidance, tests, and both generated runtime surfaces are verified, remove the entire root [`## Process hygiene`](../AGENTS.md#process-hygiene) section. Its incident-specific rules must not survive beside the replacement contract.
