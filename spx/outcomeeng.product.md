# Outcome Engineering Plugin Marketplace

## Why this product exists

Coding agent plugins to be used by consumers of the Outcome Engineering methodology. Consumers use the plugins generated by the pipeline of this product in domains that we cannot anticipate at design time.

**IMPORTANT:** Always remember: this repository is only the dogfood instance; something working here does not deliver any value. It must work for the consumers in their context and situation.

## Consumers and jobs

| Consumer / persona      | Job to be done                                                                                                                           |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Product engineers       | Apply the Outcome Engineering methodology through their coding agent while preserving their repository's language and domain conventions |
| Plugin authors          | Create portable methodology, language, and craft plugins from one authored source                                                        |
| Marketplace maintainers | Build, inspect, install, and publish agent-harness-native plugin artifacts from the shared marketplace                                   |

## Surfaces

- Coding agent plugins: product engineers invoke skills and configured agents through agent-native plugin artifacts.
- SPX CLI — product engineers and automation inspect and operate on product tree structure and verification state.
- Local browser — product engineers inspect and restructure the SPX CLI's product tree projection interactively.

## Actors and sidedness

The marketplace serves plugin producers and plugin consumers.

- Plugin authors provide authored methodology, language, and craft behavior.
- Marketplace maintainers render and publish agent-harness-native plugin artifacts.
- Product engineers consume those artifacts inside their own repositories.

## Product hypothesis

WE BELIEVE THAT a plugin marketplace delivering the Outcome Engineering methodology through coding agent plugins
WILL reduce implementation rework by capturing and encoding product truth in the product tree and enforcing deterministic context and evidence-driven verification
CONTRIBUTING TO faster product iteration at the level of malleability chosen by the operator.

### Evidence of success

| Metric                     | Current | Target | Measurement approach                                            |
| -------------------------- | ------- | ------ | --------------------------------------------------------------- |
| Context loading coverage   | 100%    | 100%   | All authoring and verification skills enforce context loading   |
| Spec-verification coupling | Partial | 100%   | Every assertion is covered by deterministic or agentic evidence |
| Plugin adoption            | N/A     | 50+    | GitHub stars + marketplace installs                             |

## Scope

- Outcome Engineering methodology
- Shared Claude Code and Codex plugin surfaces from the same source tree
- Language-specific plugins for Outcome Engineering (Python, TypeScript, Rust, Go) for architecture, tests, code, and review
- Change coordination (claim, release with a Handoff, close) for work continuity across agent sessions
- Pre-commit validation infrastructure for plugin and skill quality
- Persistent marketplace installation and isolated end-to-end install verification
- Interface surfaces (browser) that render the product tree from the SPX CLI projection and support interactive review and restructuring
