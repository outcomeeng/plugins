<merge_composition>

`executable-state-evidence` applies this composition. It operationalizes the `Merge` section of the Projection chapter, `versions/4.0/methodology/product-tree/verification/projection.md` inside the declared `methodology.source`.

- Touch: a changeset touches a node directly through its spec, its status claim, a decision record or outcome record the node holds, a verification artifact under its `tests/`, `evals/`, or `probes/`, a file its linked verification reaches, or a file one of its `[audit]` assertions names as its subject. It touches a node through a dependency through a decision record that governs the node, or a path a result pin in the node's status claim reads.
- Selected predicates: every changeset selects Validate and the coverage predicate, with the attested probe results the status claims carry. A least malleable target of `spec` adds no agentic predicate. A least malleable target of `verification` adds Review. A least malleable target of `implementation` adds the evidence audits and Review, with the evidence audits run before Review. A product spec or outcome-record change adds Review whatever the least malleable target.
- Results: a changeset that changes a pinned path invalidates that result; a node's Audit results stay valid only when every pinned change is a link-format edit. A node whose declarations are unchanged and that reached `Passing` produces each invalidated result again before merge. A node that never reached `Passing` derives `Declared` or `Specified` until every result its malleability requires is current and passes. A node whose declarations change merges in the state it derives; when the Frame requires that node `Passing`, the Frame lists each result still missing, and the Change reaches `Applied` only after those results pass.
- Producers by kind: the test runner for `[test]`, the eval harness for `[eval]`, the Author's attested run for `[probe]`, and the configured audit Verifier for `[audit]`. A result whose producer the repository does not ship names the Change that supplies it as a blocker.
- Authoring checks: each added or changed decision record receives its decision-record audit before merge, at any malleability, and that audit produces no node-local result.

</merge_composition>
